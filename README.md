# Broker Stars

Биржевая дуэль на восемьдесят секунд: Telegram mini app и приложение для Android
из одного бандла. React + TypeScript + Vite, график на Canvas 2D, симуляция —
чистый TypeScript без DOM, сервер — Cloudflare Worker с базой D1.

**Прототипом эта игра здесь больше не называется.** Слово было правдой, пока она
целиком лежала у игрока в браузере. Сейчас за ней стоит сервер, который считает
деньги, таблица лидеров, дуэли живых людей, корпорации и закрытый тест в Google
Play (`versionName 1.1.0` в `android/app/build.gradle`). Ниже оно встречается
один раз — цитатой из `src/ui/admin.ts`, который эту фразу про себя всё ещё
носит и с тех пор устарел.

Чего в игре нет — списком в конце файла, и это список несделанного, а не
невозможного.

## Запуск

```bash
npm install
```

```bash
npm run dev
```

```bash
npm run build
```

Android — тот же бандл в обёртке Capacitor. Собрать клиент в режиме `android` и
синхронизировать его в `android/`:

```bash
npm run android
```

Дальше подписанный бандл собирает Gradle из этой же папки:

```bash
cd android && ./gradlew bundleRelease
```

Ключ и пароли к нему берутся из `android/keystore.properties` — файла, которого в
репозитории нет и быть не может; рядом лежит `keystore.properties.example` и
говорит, что в него писать и почему сам ключ обязан лежать вне проекта.
Отсутствие файла **не ошибка**: дебажная сборка должна собираться на машине,
которая ключа никогда не видела, поэтому конфиг подписи просто не применяется и
`bundleRelease` выдаёт неподписанный бандл. Отказ Play — место лучше, чем ошибка
компиляции на чужом компьютере.

`versionCode` в `android/app/build.gradle` поднимается на единицу на **каждый**
покидающий машину бандл, включая пересборку того же кода: Play отказывает в
загрузке, у которой он не выше предыдущей. `versionName` — то, что читает человек,
и двигается, когда двигается игра.

Тесты симуляции:

```bash
npm test
```

Headless-прогоны для баланса:

```bash
npm run sim -- --seed=42 --runs=1000 --bot-a=medium --bot-b=random
```

```bash
npm run sim -- --seed=7 --runs=1000 --acceptance
```

`--off=marketImpact,shorting` выключает флаги в прогоне.

## Telegram

Игра — статическая страница; бот её не хостит, а только открывает. Поэтому нужны
две вещи: публичный HTTPS-адрес сборки и бот, который на него ссылается.

**1. Хостинг.** В репозитории лежит workflow `.github/workflows/deploy.yml`,
который на каждый push в `main` собирает проект и публикует на GitHub Pages.
Один раз включите Pages руками: Settings → Pages → Source → **GitHub Actions**.
После этого адрес будет `https://<пользователь>.github.io/BrokerStars/`.
`base: './'` в `vite.config.ts` уже настроен на подпапку, ничего менять не надо.

**2. Воркер.** Отвечает на сообщения теперь он же — см. `worker/README.md`,
раздел «Развернуть». Его адрес нужен на следующем шаге.

**3. Бот.** У @BotFather: `/newbot`, получить токен. Затем:

```bash
cp .env.example .env
```

Впишите в `.env` токен, адрес сборки из шага 1 и адрес воркера из шага 2. Файл в
`.gitignore` — токен в репозиторий не попадёт. Дальше:

```bash
npm run bot
```

**Это не демон.** Скрипт настраивает бота и выходит: ставит вебхук на `/tg`
воркера, вешает синюю кнопку **PLAY** рядом с полем ввода (`setChatMenuButton`)
и регистрирует команды. Всё это живёт на стороне Telegram, так что после
единственного запуска бот отвечает всегда и держать ничего не надо.
`npm run bot -- --off` снимает вебхук обратно.

Раньше здесь был long polling, и цикл был всем ботом: чтобы кто-то ответил на
`/start`, что-то должно было работать. Больше нет. Токен и так лежит в воркере —
без него не проверить, кто сдаёт результат и кто садится за дуэль, — так что
пусть он и отвечает (`worker/src/bot.ts`). Пароль вебхука не заводится отдельно,
а выводится из самого токена: обе стороны считают HMAC одной метки под одним
токеном, поэтому синхронизировать нечего.

Зависимостей у скрипта нет, только Node 18+ ради встроенного `fetch`.

**Что игра берёт из Telegram.** Полную высоту, запрет вертикальных свайпов, цвет
хрома под фон игры и haptic feedback на кнопках сделок. Имя игрока на карточке
подставляется из `initDataUnsafe.user` — это чисто косметика, данные оттуда
клиентские и непроверенные, никаких решений на них не завязано.

Ничего из этого игра больше не берёт **сама**: всё идёт через `src/platform/`, и
почему — следующий раздел.

## Где игра работает

Игра открывается тремя способами, и это единственное место, где они различаются.

| Хост | Кто игрок | Чем подписан |
|---|---|---|
| Telegram mini app | тот, кого Telegram уже знает | `initData`, HMAC по бот-токену |
| Android-приложение | никто, пока не вошёл через Google | сессия воркера, `bs1.…` |
| Обычная вкладка | никто | ничем, либо гостевой сессией |

**Раньше про это знали шесть файлов.** Они сами лезли в `window.Telegram.WebApp`:
кто игрок, что сказала ссылка запуска, как отдать ссылку другу, дрожит ли телефон
на тапе. Десять мест на семнадцать тысяч строк — и ровно эти десять и были всем,
что привязывало игру к Telegram. Теперь они ходят через `src/platform/index.ts`,
а сборка, которая не мини-апп, — это третий файл рядом с `telegram.ts` и `web.ts`
плюс строка в выборе. Ничему выше этого модуля про новый хост узнавать не
приходится.

Ничего здесь не мемоизировано, и это намеренно: объект `window.Telegram` кладёт
тег скрипта в `index.html`, и один опрос, случайно случившийся раньше него,
навсегда отвечал бы «обычный браузер».

### Android

Тот же бандл в Capacitor-WebView (`npm run android`, обёртка в `android/`). Всё
отличие в том, что личность здесь никто не выдаёт: игрок анонимен, пока сам не
перестанет, и вход — это то, что происходит **внутри** игры, а не то, что
случилось до неё.

**Хранится не токен Google.** Google ID token живёт около часа, а подпись читается
перед каждой записью — игра, будящая Credential Manager раз в час, это игра,
которая всё время просит разрешения, чтобы в неё играли. Поэтому токен один раз
уходит на `/auth/google` и возвращается **сессией самого воркера** (`bs1.…`,
`worker/src/auth.ts`), годной 180 суток и проверяемой арифметикой. Она и лежит в
`localStorage`, и её несёт каждый запрос — в том же поле `initData`, в котором
ездит подпись Telegram, потому что это имя поля на сервере, а переименование
здесь означало бы переименование обратно у сокета.

**Id разведены по пространствам имён, и в этом вся миграция.** Телеграмные id
остаются голыми цифрами — теми же строками, что уже лежат в `players.id`, — а
гугловые приезжают с префиксом `g:`, с которым число столкнуться не может. Два
сорта игроков, одна база, ни одной миграции.

Не вошедший игрок играет: матчи с ботами, монеты, комната, гардероб — всё
локально, ровно как всегда играла обычная вкладка. Вход покупает то, что обязан
хранить сервер: таблицу, дуэли, друзей и профиль, переживающий новый телефон.

### Гость

Telegram выдаёт личность до первого кадра. Больше никто: и вкладка, и свежая
установка — это никто, а никого нельзя нигде записать — ни в таблицу, ни в дуэль,
ни в друзья. Именно так приглашение, отправленное из Android-сборки, превращалось
в ссылку на страницу, где адресат мог посмотреть и не сесть.

Поэтому воркер готов поручиться за того, о ком ничего не знает: `src/ui/guest.ts`
просит гостевую сессию, и дальше гость — обычный игрок. Порядок такой: токен
хоста всегда сильнее (подпись Telegram или сессия, полученная входом через
Google), гость — то, во что `initData()` проваливается, и только потом.

Чем платит игрок: гость живёт в хранилище этого браузера и больше нигде. Почистил
данные, переустановил, сменил телефон — гостя нет. Поэтому вход через Google
**забирает гостевой сейв с собой**, а не заводит рядом пустой: `/auth/google`
принимает поле `guest` ровно за этим.

### Связывание

Человек играл в Telegram, поставил приложение, вошёл через Google — и нашёл
пустой офис: два аккаунта, два id и ничего, что говорило бы, что это один
человек. Связывание и есть это «говорить» (`src/link/protocol.ts`, строка АККАУНТ
в настройках).

**Доказывается не заявлением, а владением обоими.** Аккаунт, у которого сейв,
чеканит код; аккаунт, который присоединяется, его вводит; сервер видит две
подписи, а не одно утверждение. Отсюда всё остальное: код короткий, живёт десять
минут и существует ровно в одном экземпляре — пока он есть, это пароль к чужому
сохранению. Восемь символов того же алфавита, что у дуэльных и дружеских кодов:
base32 без гласных, ни одного слова и ни одной пары, которую путает телефонная
клавиатура.

Направление одностороннее намеренно: гугловый аккаунт присоединяется к
телеграмному, никогда наоборот. Почему — в `worker/migrations/010-identities.sql`.

### Обратная связь

Строка ОБРАТНАЯ СВЯЗЬ в настройках открывает поле и отправляет написанное
(`src/feedback/protocol.ts`, `worker/src/feedback.ts`). Длины и пауза между
сообщениями лежат в общем файле, поэтому кнопка гаснет ровно на том условии, на
котором сервер отказал бы, — никто не пишет отчёт, чтобы узнать постфактум, что он
слишком короткий. Нижняя граница в десять символов — настоящий фильтр: краулер
Google Play обходит каждую кнопку в каждой сборке, и он находит и это поле тоже, а
тап и написанная фраза — разные вещи.

**Ничего не хранится.** Сообщение читается из запроса, уходит в Telegram и
забывается: нет таблицы написанного — нет строки, которую можно потерять, выдать
или забыть удалить вместе с аккаунтом. Записывается одна метка времени, что
кто-то что-то отправил, и это кулдаун, в котором нет ни одного его слова.

Куда именно оно приходит, игра не называет **вообще**, и это не небрежность: сейчас
бот несёт отчёт в личку `ADMIN_ID`, а заявленный адрес — почта, и он ею станет в
тот день, когда будет чем слать. Кнопка, обещающая письмо, пока текст идёт в
Telegram, — это ложь человеку, который делает тебе одолжение.

### Удаление аккаунта

`POST /profile/delete` с явным подтверждением сносит все таблицы, ключёванные на
игроке, **одной пачкой**: полуудалённый игрок хуже неудалённого. Дружбы уходят с
обеих сторон — список с мёртвым именем это и есть то, чего удаление должно было
не оставить. Google Play требует, чтобы удаление можно было начать и **снаружи**
приложения, поэтому рядом лежит страница `public/delete-account.html`.

## Меню, комната, магазин и монеты

**Мягкая валюта называется монетами, и раньше называлась звёздами.** Переименование
не косметическое: у Telegram есть своя валюта Stars, за которую планируется продавать
доллары, — и магазин, который просит «звёзды», спрашивал бы, какие именно, в диалоге,
где ошибка стоит настоящих денег. В игре больше нет ничего, что называлось бы
звездой: ни в текстах, ни в значке, ни даже в галочке на полке наград.

Чего переименование **не** коснулось — колонок в базе. `players.stars` и
`results.stars` как назывались, так и называются: имя столбца игроку не видно, а
миграция ради него не покупает ничего. Провод переименован, но сервер release-другой
отдаёт оба имени сразу (`coins` и `stars`), а клиент читает `coins ?? stars`, — иначе
между автодеплоем игры на Pages и ручным деплоем воркера кто-то остался бы без
баланса. Обе заглушки помечены в коде и снимаются, когда старые бандлы выйдут из
обращения.

Название самой игры — Broker Stars — не тронуто: это имя продукта, репозитория,
бота и адреса, а не валюты.

Игра открывается на меню: комната игрока во весь экран, одетый герой стоит в ней,
шестерёнка слева сверху, счётчики долларов и монет справа, карточка следующего
шага ремонта и две колонки кнопок внизу. Заголовка «BROKER STARS» на этом экране
больше нет — сценой стала сама комната.

**Две рельсы по краям, по одной круглой кнопке на каждой, и значат они
противоположные вещи.** Слева — то, что приходит: день, который загорается и к
полуночи гаснет, единственное в игре, что так себя ведёт. Справа — то, кто ты:
профиль, который не меняется, пока его не меняет сам игрок. Колонка из трёх на
одной стороне сообщала только то, что их три: там висели ещё друзья и
корпорации, и рельса тихо становилась местом для всего, что больше никуда не
влезло.

Внизу слева колонка из четырёх — `SHOP`, `MARKET`, корпорация и `RATING`, то есть
**тратить · изучать · состоять · стоять в таблице**, в том порядке, в каком игрок
с ними встречается. Справа `PLAY`, под ней `DUEL` в две трети высоты: та же
дорога, но та, для которой нужен человек на другом конце, и она не должна
соперничать с той, для которой не нужен никто.

Правило, по которому кнопка попадает в колонку, а не на рельсу: колонка — это
места, **куда идут**, рельса — то, **на что смотрят** и что собирают. Корпорация
сломала это правило первой и поэтому уехала в колонку: в корпорацию именно что
идут. Друзья уехали внутрь профиля по обратной причине — список людей это тоже
не новости, а ссылка, код и список это то, за чем ходят один раз.

В левом углу раньше висела кнопка справки и больше ничего. Теперь угол открывает
настройки, и в них шесть строк: **справка**, **посмотреть туториал**, **язык**,
**аккаунт**, **обратная связь** и **политика конфиденциальности**. Три из них
условные: аккаунт рисуется там, где есть что связывать, обратная связь — там,
где есть куда отправить и чем подписать, а туториал — там, где его есть чем
показать (см. «Где игра работает» и «Тур по меню»). Политика стоит последней,
потому что за ней в настройки не приходят, и присутствует вообще потому, что
Google Play требует ссылку на неё изнутри приложения, а не только в листинге.
Монеты из-за всего этого переехали направо, а доллары встали внутрь от них:
монеты сидят в своём углу с первой сборки, и подвинуть их ради новой валюты
стоило бы дороже, чем купило.

### Языки

Игра есть на английском и русском (`src/ui/i18n.ts`). Переключается в настройках,
выбор лежит в `localStorage` под `brokerstars.lang`.

**Фиксированного языка по умолчанию нет.** `pickLang` спрашивает три источника по
порядку. Сохранённый выбор бьёт всё: человек, ткнувший язык в настройках, уже
сказал, чего хочет, и никакая догадливость про его телефон этого не стоит. Потом
догадка хоста — Telegram знает язык, потому что игрок выбрал его в Telegram;
браузер и WebView знают, потому что его знает устройство. Читается только первый
субтег, так что `ru-RU`, `ru_RU` и `ru` — один язык. И только потом
`DEFAULT_LANG`, английский, — для хоста, который не сказал ничего.

Причина в том, что фиксированный ответ всегда здоровался с кем-то не на том
языке: русский неверно встречал весь мир, английский — половину тех, кто в эту
игру пришёл. А экран, на котором надо сперва найти настройки, чтобы прочитать
остальные, — плохой первый кадр.

Текста в игре два сорта, и хранятся они по-разному нарочно.

**Обстановка экрана** — кнопки, заголовки, отдельные фразы — лежит в `i18n.ts` на
обоих языках под именем-ключом. Русская таблица типизирована по английской, так
что ключ, который есть в одной и отсутствует в другой, не соберётся.

**Содержание** — какая компания, что делает предмет, что за лига — остаётся в
своём файле данных (`sim/companies.ts`, `ui/leagues.ts`, `ui/wardrobe.ts`,
`ui/renovation.ts`) по-английски, а `i18n.ts` несёт для него только русский, под
тем же id, которым пользуются данные. Добавить компанию стоит одной строки в
одном файле, а не трёх, и непереведённая покажет английский текст вместо голого
ключа. Чтобы этот запасной путь не стал местом, где прячутся забытые строки,
`i18n.test.ts` падает на любом пропущенном id — и на лишнем, которого в данных
уже нет.

**Названия компаний не переводятся.** TET CORP остаётся TET CORP на обоих языках:
это тикеры, по ним игрок узнаёт компанию на графике и на рынке.

Текущий язык — модульное состояние, а не контекст: все экраны висят на одном
компоненте, который перерисовывается при смене, поэтому `t()` можно звать откуда
угодно, не протаскивая проп через девять файлов.

Дев-панель и дев-кнопки на меню остались английскими намеренно: их видит тот, кто
их писал.

**Место под текст.** Русские слова длиннее английских, и два места это вскрыли.

Строка `CASH / HELD` на карточке трейдера стояла в одну линию, и подпись с числом
рядом занимали ширину обеих вместе — места хватало ровно на два английских слова
по четыре буквы, да и то впритык: `CASH 9 293 HELD 724` вылезал на три пикселя за
свою коробку на 320 pt ещё до всякого перевода. Подпись переехала **над** числом,
и теперь половинка шириной с большую из двух строк, а не с их сумму. Влезает на
обоих языках с запасом.

Имя предмета в описании обрезается многоточием, если длинное, — и обрезает оно
десять английских названий из двадцати пяти на той же ширине. Это поведение
самого макета, а не перевода; русские имена подобраны короче, так что не
обрезается ни одно.

### Тур по меню

Всё, что игра умеет, лежит за кнопкой на одном экране, и ни одна кнопка не
говорит, зачем она. Поэтому при первом открытии поверх меню идёт тур
(`src/ui/tutorial.ts`, `TutorialOverlay.tsx`): шаг называет **метку** в разметке
меню, оверлей подсвечивает её и гасит остальной экран, а текст лежит в `i18n.ts`
под `tut.<id>.title` и `tut.<id>.body`.

**Метки, а не CSS-селекторы.** Шаг указывает на `data-tut="play"`, а не на
`.menu-btn.play`. Тур переживает перерисовку стилей, а метка, которой в меню
больше нет, просто роняет свой шаг, вместо того чтобы подсветить пустой пол.

**Шесть шагов, и было тринадцать.** Тринадцать — это три с половиной тысячи
знаков текста между человеком, открывшим игру, и игрой. Большая часть описывала
кнопки, которые описывают себя сами. Тур читают один раз и читает его тот, кто
хочет начать; каждое предложение, которое он пролистал, могло быть тем, которое
ему было нужно. Сейчас 576 знаков — на 83 % меньше, на обоих языках.

| # | Шаг | Что подсвечивает |
|---|---|---|
| 1 | дуэль | `PLAY` и `DUEL` вместе |
| 2 | друзья | профиль |
| 3 | деньги | два счётчика наверху |
| 4 | акции | `MARKET` |
| 5 | одежда | `SHOP` |
| 6 | офис | карточку ремонта |

**Осталось то, до чего никто не доходит сам.** Одежда меняет матч и работает,
только пока надета. Офис — это деньги на открытии, и тур по-прежнему называет
все четыре его числа. Доллары покупают настоящие доли в компаниях, против
которых ты играл. Дуэль — это против человека, и ссылку ему отправляешь ты. Ровно
эти четыре вещи закреплены в `tutorial.test.ts` — благодаря чему такое сокращение
можно было сделать, не гадая, что важно.

**Ушло** приветствие, объяснявшее, что тур — это тур; `PLAY`, который в одном
тапе от того, чтобы объяснить себя; правила обновления полки, которые магазин
печатает у себя на полке; `RATING` и `SETTINGS`, то есть таблица и шестерёнка. Где
два шага описывали две половины одного экрана — магазин и гардероб, бонус и
баланс, — остался один шаг, потому что остался один экран.

Шаг про деньги подсвечивает два счётчика и **не** трогает стоящий рядом кейс дня:
все три вместе рисовали овал во весь верх экрана, который учит меньше, чем
тесный. Кейс — единственная кнопка в игре, которая горит сама, и предложение
называет её словами.

**Виделся или нет — знает только это устройство**, `brokerstars.tutorial` в
`localStorage`. Нарочно не в профиле: это факт про браузер, видевший оверлей, а не
про то, чем игрок владеет. Помечается увиденным в момент **открытия**, а не
завершения: хранилище, которое недоступно, отвечает «не видел» всегда, и тур
здоровался бы при каждом запуске — так он хотя бы закрывается один раз за сессию.
Пересмотреть можно из настроек, строкой ПОСМОТРЕТЬ ТУТОРИАЛ.

**Самого матча в туре нет.** Одна фраза говорит, что `PLAY` — это восемьдесят
секунд против бота, и на этом всё. Что происходит внутри этих секунд — забота
СПРАВКИ; тур, остановившийся объяснять шорт, закрыли бы раньше, чем он дошёл до
того, что человек сам не откроет.

### Ремонт офиса

Раньше это была спальня, и спальня ушла: трейдер, который гриндит лиги ради
кровати получше, ремонтировал не ту комнату. Теперь ремонтируется то место,
откуда играют, — стол, машина на нём и стены вокруг.

Стартовый офис — набор `poor`, каждый шаг ремонта заменяет один слой на
нормальный. Порядок, цены и прибавка к стартовому капиталу — в
`src/ui/renovation.ts`, всё в одном массиве:

| # | Что | Монет | К старту | Стартовый капитал |
|---|---|---|---|---|
| 1 | стены и пол | 20 | +25 | 10 025 |
| 2 | окно | 60 | +50 | 10 075 |
| 3 | стол | 110 | +75 | 10 150 |
| 4 | компьютер | 150 | +100 | 10 250 |
| 5 | шкаф | 190 | +125 | 10 375 |
| 6 | плакат | 220 | +150 | 10 525 |
| 7 | второй плакат | 250 | +175 | 10 700 |

**Цены: всего 1000 монет, намеренно десятая часть гардероба** (7750). Форма
подчинена двум правилам. Ни один шаг не дороже второй ступени слота (uncommon
стоит 200, самый дорогой шаг здесь 250), и **первый шаг за 20 остаётся самой
дешёвой покупкой в игре**, дешевле даже common. Он и есть урок про трату: висит
на меню с первой минуты и должен быть по карману в первый же вечер. Раньше
перекос был в другую сторону: восемь шагов стоили 144 монеты против гардероба в
415, то есть комната была четвертью всего покупаемого и заканчивалась за вечер.

**Прибавка к старту: лесенка по 25, всего +700 на стартовые 10 000.** Комната
была единственным, что покупается и ничего не делает, — картинка за меню и ни
одного числа в матче, тогда как каждая ступень слота выдаёт перк. Косметика по
цене перка — это косметика, которую никто в здравом уме не берёт, и лечится это
не ценой, а колонкой «к старту»: цены остались где были, комната по-прежнему
дешёвая покупка, просто больше не пустая.

Потолок в 700 выбран по трём причинам.

- **Ниже лучшей вещи слота.** Легендарные руки обнуляют комиссию и режут
  проскальзывание до 0.65 — за насыщенный матч это порядка пяти процентов книги,
  и стоят они 600 монет против 1000 за весь офис. Комната, которая их бьёт,
  сделала бы самую дешёвую покупку в игре самой сильной, а гардероб — то есть
  месяцы игры — ловушкой для дураков.
- **Но заметно.** Соперник садится с ровными 10 000, а выигрывает тот, у кого
  книга шире, так что +7 % — это несколько процентных пунктов винрейта:
  законченный офис есть смысл заканчивать, но плохой матч он не вытащит.
- **Ступени растут, отдача с монеты падает** — 25 долларов за первые 20 монет и
  175 за последние 250. Это та же кривая, что у ступеней редкости (common 50 →
  legend 600 за всё меньшую прибавку), и она оставляет щедрым именно дешёвый
  первый шаг, ради которого он и стоит первым.

Бонус **прибавляется** к `CONFIG.match.startingCash`, а не заменяет его: бот
всегда садится с ровной десяткой, и эта асимметрия и есть смысл — ремонт
чувствуется форой, а не гасится соперником, который тоже отремонтировался. В
дуэли ремонт обеих сторон читает сервер из профилей, и книги у них разные (см.
«Дуэль»). Число не хранится нигде: оно каждый раз считается из количества шагов
(`roomCash`), так что таблицу можно перебалансировать без миграции.

Всё, что меряет матч от его начала — планка прибыли в +40 %, проценты на
карточках трейдеров, пунктир безубытка на графике капитала, — спрашивает
**трейдера** (`TraderState.startCash`), а не конфиг. Иначе две разные книги
мерились бы одной линейкой, а планка +40 % тихо выдавалась бы за меньший рост.

По тому, что платят лига и задания, весь офис — от двух до пяти недель, то есть
он заканчивается, пока гардероб ещё в месяцах впереди.

Покупка в два тапа: цена превращается в крестик и галочку, и пока висит вопрос,
комната **уже показывает результат** — слой подменяется на нормальный, отмена
возвращает как было. Так видно, за что платишь, до того как заплатил.

Пяти слоёв в бедном офисе нет вовсе, и до своего шага они просто не рисуются:
стола, компьютера, шкафа и обоих плакатов. Пустой офис — лучший первый кадр, чем
плохо обставленный: он читается как то, что надо построить, а не как то, что надо
прибрать. Порядок отрисовки снизу вверх: `bg → window → picture_1 → picture_2 →
shelf → table → comp`. Сцена рисуется **двумя стопками**, по одной с каждой
стороны от персонажа: стол и компьютер он загораживать не должен — он за ними
сидит, — а окно, плакаты и шкаф висят на стене и фигуру не пересекают никогда.

Спрайты (`public/textures/room/`) лежат на общем холсте 1080×1920, так что офис,
как и персонаж, собирается наложением без сдвигов. Это единственное место в игре
с WebP: девять полноэкранных слоёв в PNG весили 7.1 МБ, больше всего остального
вместе взятого, а на качестве 90 — 0.57 МБ и ни одного отличимого пикселя.

Прогресс — это просто число выполненных шагов, и живёт оно **на сервере** (см.
«Комната и гардероб на сервере»); в `localStorage` под `brokerstars.room`
остаётся копия, которую меню рисует, пока не пришёл первый ответ.

Фигура персонажа намеренно небольшая и сдвинута вправо от центра; как только
куплен стол, она поднимается (`.hero-seated`), иначе ближний край стола резал бы
её по плечам и трейдер читался бы стоящим за столом, а не работающим за ним.

Монеты начисляются за матч по таблице в `src/ui/progress.ts`:

| Исход | Монет |
|---|---|
| победа | 3 |
| ничья | 1 |
| поражение | 0 |
| капитал вырос на 40 % и больше | +2 сверху |

Бонус начисляется независимо от исхода, поэтому проигранный, но хорошо
отторгованный матч всё равно что-то приносит. Планка именно «+40 %», а не «в
плюсе»: рынок сам по себе растёт, в плюсе заканчиваются **96 %** матчей, и награда
за это была бы не бонусом, а частью базовой ставки. Планку в 40 % берут 38 %
матчей. На экране результата видно разбивку.

Сорок процентов считаются **от своей книги**, а не от ровной десятки: ремонт
офиса добавляет к стартовому капиталу, и планка, прибитая к конфигу, выдавала бы
законченному офису бонус за рост в 31 % (см. «Ремонт офиса»).

Баланс тоже считает сервер: заработано минус потрачено (см. «Комната и гардероб
на сервере»). В `localStorage` под `brokerstars.coins` лежит та же копия для
первого кадра и для сборки, за которой сервера нет; все обращения к хранилищу
обёрнуты в try/catch — в приватном окне и в некоторых webview доступ к нему
бросает исключение, и игра не должна на этом падать.

Мета намеренно живёт в `src/ui/`, а не в `sim/`: симуляция про монеты ничего не
знает, матч считается одинаково независимо от того, платят за него или нет.

### Магазин и гардероб

**Кнопка в меню одна — `SHOP`, — а экран (`src/ui/Shop.tsx`) под двумя вкладками:
что продаётся сегодня и что уже лежит в шкафу.** Раньше это были две кнопки в
меню, хотя компонент всегда был один: сетка та же, карточки те же, превью то же,
и разница только в том, какие вещи в списке. Дорога, которую игрок на самом деле
проходит, — «купить шляпу, надеть шляпу», — и она шла через меню дважды. Выбранная
вещь переживает переключение вкладки, так что только что купленное лежит под
пальцем на соседней.

Тап по карточке сразу примеряет вещь на превью и показывает под сеткой, что она
даёт; кнопка внизу делает нужное действие: `BUY` / `WEAR` / `WEARING`.

Пять слотов (`hat`, `neck`, `torso`, `hand`, `access`) × пять редкостей, всего
двадцать пять вещей. Игрок начинает голым — с волосами, без руки, — но не
насовсем: за **первый доигранный матч** сервер дарит бандану, самую дешёвую вещь
самого дешёвого слота (`giftHat` в `worker/src/profile.ts`). Первый матч играется
на доске, которую новичку не показали, — а показывает её как раз первая вещь в
шкафу, которой у него нет. Правило подарка — «на голове ничего нет», а не
«сыграно ровно один матч»: оно идемпотентно, не требует счётчика и достаётся тем,
кто играл ещё до того, как подарок появился. Из `spent` при этом не снимается
ничего: подарок, оплаченный из баланса, — не подарок.

**Порядок редкостей:** `common → uncommon → rare → mythic → legend`. Мифик стоит
**ниже** легендарки, а не выше — это одна из тех вещей, которые в разных играх
устроены по-разному, так что порядок задан ровно в одном месте, массиве
`RARITIES`, и всё остальное (цены, цвета, каталог, веса соперника, таблицы в
`ui/perks.ts`) читается по позиции в нём.

**Лестницы внутри слота больше нет: магазин выкладывает пять вещей в день.**
Раньше на полке лежал весь каталог сразу и покупался ступенька за ступенькой —
всё всегда было на месте, и единственным вопросом было, оплачено ли то, что
лежит ниже. Это делало магазин прайс-листом: ничто никогда не было новостью,
ничто не пропадало к завтрашнему дню, а дешёвая вещь, которая не нужна, стояла
между игроком и дорогой, которая нужна.

Теперь `src/shop/protocol.ts` тянет `OFFER_SIZE = 5` вещей на сутки — те же
UTC-сутки, что у бонуса и у котировок, — и любую из них можно купить в любом
порядке, как только есть монеты. Что уже куплено, не предлагается никогда, так
что полка усыхает по мере наполнения шкафа, а в день, когда куплены все двадцать
пять, она пуста навсегда.

| редкость | цена | шанс на одну вещь в раздаче |
|---|---|---|
| common | 50 | 40 % |
| uncommon | 200 | 26 % |
| rare | 300 | 17 % |
| mythic | 400 | 11 % |
| legend | 600 | 6 % |

Веса читаются процентами не случайно: в каждом слоте ровно одна вещь каждой
редкости, то есть пять штук на вес, и доля редкости в первой раздаче — это `5·w`
из 500. Голый шкаф видит common в двух раздачах из пяти, а легендарку примерно на
каждой третьей полке. «Сначала дешёвое» эти веса больше не обеспечивают, и не
должны: новичка держит в commons то, что легендарка стоит в двенадцать раз
дороже, а ждать её стоит потому, что она выпадает раз в три дня.

**Сид раздачи — сами сутки, без игрока в нём.** Двое с одинаковым шкафом видят
одну и ту же полку, а у кого шкаф полнее — видит, что от неё осталось. Это
сделано нарочно: магазин, на который вся лига смотрит одним утром, — это то, о
чём можно поговорить, а посидовый по игроку не купил бы ничего, кроме
невозможности сказать «сегодня дают стетсон».

**Полка хранится, а не пересчитывается на каждый запрос.** Раздача — чистая
функция от дня и от того, чем игрок владел в момент броска, так что её можно было
бы не записывать вовсе — если бы покупка не меняла второй аргумент. Пересчёт
после покупки выложил бы шестую вещь на полку из пяти. Поэтому бросок делается
один раз и запоминается (`rolledOffer`), а покупка умеет только снимать с него.
Копия лежит в `localStorage` под `brokerstars.offer`, и здесь она важнее обычной
копии «для первого кадра»: офлайн это единственное, что мешает полке молча
обновляться после каждой покупки.

Обе половины импортируют один файл: браузер рисует полку, сервер по ней и
списывает, и заявка на то, чего сегодня не выкладывали, отклоняется —
`not on sale today` в `worker/src/profile.ts`. Цены (`PRICES`) — 50 / 200 / 300 /
400 / 600, слот целиком по-прежнему стоит 1550 монет, каким бы путём его ни
собрали.

**Почему так дорого.** Кривая была 4 / 7 / 12 / 20 / 40, и беда была в размере, а
не в форме: при том, что платит лига, каждая вещь стоила примерно пятую часть
вечера, а весь гардероб собирался за шесть дней. Одежда выдаёт перки, меняющие то,
как играется каждый следующий матч, — слот шеи выдаёт абилки прямо, — то есть была
одновременно самым сильным рычагом в игре и самой дешёвой вещью в ней. Семь монет
за абилку — это не цена.

**Форму задаёт лига.** Она платит 2.2 монеты за матч в бронзе и 12.2 под короной, а
задания на день добавляют ещё около 7.5 сверх сыгранного. На этом фоне, при восьми
матчах за вечер, цены дают **2 / 5.6 / 5.9 / 5.5 / 5.7 дня на одну вещь** в той
лиге, где этот тир и покупается:

| тир | цена | дней на вещь (4 / 8 / 12 матчей в день) |
|---|---|---|
| common (бронза) | 50 | 3.1 / 2.0 / 1.5 |
| uncommon (серебро) | 200 | 9.2 / 5.6 / 4.0 |
| rare (золото) | 300 | 10.3 / 5.9 / 4.2 |
| mythic (глобал) | 400 | 10.0 / 5.5 / 3.8 |
| legend (корона) | 600 | 10.7 / 5.7 / 3.9 |

Это то самое свойство, которое старые числа только декларировали: ступень стоит
примерно одинакового числа вечеров, где бы ты на лестнице ни стоял, потому что
цены растут с тем же темпом, с каким растут выплаты.

**Common выбивается намеренно.** Два дня — вдвое дешевле в вечерах, чем всё, что
выше. Первая покупка это не награда за гринд, а урок про то, что магазин существует
и что лежащее в нём решает матчи; при цене в 200 игрок пять дней читал бы на экране
матча «NOTHING TO USE · BUY A NECK ITEM», не владея вообще ничем.

Весь гардероб — **7750 монет**, от трёх до семи месяцев в зависимости от того,
сколько человек играет. Это горизонт, и он таким и задуман. Комната подорожала
следом и стоит теперь 1000 — десятую часть гардероба, см. «Ремонт офиса».

Таблица выше писалась при лестнице, когда тир и лига совпадали по построению.
С полкой на пять вещей это соответствие стало нестрогим — легендарка может выпасть
бронзовому игроку в первую неделю, — но арифметика вечеров осталась той же: цена
делится на то, что лига платит за вечер, а не на то, в каком порядке вещи
попадаются.

### Что одежда делает

Четыре слота из пяти работают так: один слот — одна способность, редкость её
масштабирует. Пять кривых игрок держит в голове, двадцать пять несвязанных
эффектов — нет. Шея — исключение, см. ниже.

| Слот | За что отвечает | От common к legend |
|---|---|---|
| HANDS | сколько стоит торговать | комиссия −15 % → бесплатно, потом ещё и выход по средней |
| BODY | насколько плохо может стать | банкротство с −500 → нельзя обнулиться → автовыход из просадки → возврат половины первого убытка → отмена сделки |
| NECK | что ты умеешь делать | пять разных абилок, не лестница одного эффекта — см. «Абилки» |
| EXTRA | что ты знаешь о рынке | вид компании на ряду → доска до матча → предупреждение о новости → направление по удерживаемой → 2 секунды будущего на графике |
| HEAD | какая достанется доска | состав до READY → реролл → бан компании → пин компании → выбираешь все три сам |

Тексты в `CATALOGUE` (`wardrobe.ts`), числа — в `src/ui/perks.ts`; тест
`perks.test.ts` проверяет, что обещанное на карточке совпадает с тем, что игра
реально применяет, — проценты для четырёх слотов и название абилки для шеи.

Стартовых денег одежда **не даёт** — это делает ремонт офиса, и только он.
Обучение одно время обещало обратное, и обещало на пустом месте.

### Абилки

Шея раньше платила монеты: +5 % за common и до +25 % за легендарку. Решения в
этом не было никакого — надел лучшее, что купил, и забыл. Теперь это единственный
слот, который даёт **действие в матче**, и единственный, где редкости не лестница
одного эффекта, а пять разных инструментов.

| Рунг | Абилка | Что делает |
|---|---|---|
| common | STATIC | 5 секунд соперник не открывает новых позиций. Выйти из того, что держит, может. |
| uncommon | HALT | 10 секунд никто не торгует компанией, в которой соперник сидит глубже всего. Ты в том числе. |
| rare | DOSSIER | До конца матча видно, что держит соперник. |
| mythic | MARGIN CALL | Закрывает все позиции соперника там, где они стоят. |
| legend | RUMOUR | 6 секунд рынок двигает твою крупнейшую позицию в твою сторону. |

**Одна на матч, одно нажатие, без выбора цели.** Цель читается с доски в момент
срабатывания: HALT берёт то, во что соперник вложен сильнее всего, RUMOUR — твою
крупнейшую позицию. Матч идёт 80 секунд на телефоне, и режим прицеливания стоил
бы больше тапов, чем абилка того стоит. Решение, которое абилка задаёт, — *когда*,
а не *во что*; «когда» и так вопрос потруднее.

Живёт всё это в `src/sim/abilities.ts`, а не в UI: абилки двигают цены и
запрещают сделки, а матч обязан воспроизводиться по сиду. RNG внутри не
используется вообще, так что тот же матч с теми же нажатиями — тот же матч.
Запреты применяются в `plannedQty` (`shutOut`), эффект RUMOUR идёт через тот же
канал `impact`, которым двигает цену крупная заявка.

**Абилка есть и у бота, та же самая.** Соперник получает ровно то, что надел
игрок, — иначе едет лестница: винрейты лиг мерились, когда абилок не было ни у
кого, и выдать абилку одному игроку означало бы молча облегчить каждую ступень.
Момент бот выбирает чтением доски, а не по таймеру (`maybeFireAbility` в
`bot.ts`): STATIC и HALT — когда соперник впереди, MARGIN CALL — когда у него
набежала прибыль, RUMOUR — когда сам стоит достаточно крупно.

DOSSIER — единственная, которая боту как таковая не нужна: она покупает взгляд в
чужую книгу, а у бота нет глаз. Чтобы рунг не был для него мёртвым, владение
DOSSIER заставляет бота вдвое реже пропускать движения в тех компаниях, где
соперник вложен, — то есть информация превращается во внимание.

Проверено на 300 зеркальных матчах на каждую абилку: винрейт держится в 44—52 %,
доля близких матчей 75—79 %, банкротств 0 %, и бот находит момент выстрелить в
95—100 % матчей. RUMOUR заметно поднимает итоговый нетворт (12 282 → 14 068) —
она легендарная и должна; HALT наоборот опускает (→ 11 250), потому что бьёт по
обоим.

**Где проходит шов.** Перки бывают двух сортов, и это разные объекты.

Всё, что меняет условия торговли, — `TraderPerks` (`src/sim/perks.ts`). Он лежит
**на трейдере**, а не в `CONFIG`: конфиг общий на матч, и скидка на комиссию,
положенная в него, досталась бы заодно и сопернику. Бот получает `NO_PERKS` и
торгует ровно так же, как торговал всегда. Симуляция при этом не знает слова
«одежда» — она знает только, что у двух трейдеров могут быть разные издержки,
разный порог банкротства и стоп, который срабатывает сам.

Всё остальное — `UiPerks`: что нарисовано, что раскрыто, сколько заплатил матч.
Оно не доходит до `sim/` вообще. **Жёсткое правило: ни одна способность не
двигает цены** — соперник торгует ту же доску, и матч обязан остаться
симметричным. На это есть тест: два матча с одним сидом, у одного игрока
бесплатная торговля, лента совпадает тик в тик.

Отмена сделки (`undoLast`) восстанавливает книгу из снимка, а не проигрывает
сделку назад: обратная арифметика средней цены входа теряет точность, а отмена,
которая молча сдвинула бы линию безубытка, хуже, чем никакой. Влияние сделки на
рынок при этом намеренно не откатывается — оно уже в чужих ценах и само затухает
за несколько тиков.

Спрайты (`public/textures/shop/`) экспортированы на общий холст 474×732, поэтому
персонаж собирается простым наложением картинок без сдвигов — этим занимается
`src/ui/Character.tsx`. Тот же компонент стоит на карточке игрока в матче, так что
купленное видно во время игры; соперник остаётся плоским `player2.png` — он бот, и
разная подача заодно помогает не путать, кто где. Порядок слоёв снизу вверх:

```
body → torso-down → neck-down → torso-up → neck-up → face → hair → hat
     → предмет в руке → access → hand
```

Где чья половина, описано картой `PIECES` в `wardrobe.ts` — три формы:

- `both` — вещь разрезана надвое, чтобы то, что идёт под воротник, ушло под него,
  а воротник лёг сверху: все торсы, `neck-common` (цепочка с бейджем),
  `neck-mythic` (бабочка — ремешок под, бант перед) и `neck-legend` (подвеска);
- `up` — одна картинка, но лежать должна поверх воротника; сейчас таких нет;
- отсутствует в карте — обычная одиночная картинка в нижнем проходе, как оба
  галстука: у них нижняя часть вклеена в общий спрайт.

Ключи карты обязаны совпадать с именами файлов `<slot>-<rarity>[-up|-down].png`.
Если не совпадут, слой просто не отрисуется — поэтому `Character.tsx` вешает на
каждый слой `onError`: битый слой прячется, а в консоль в dev-сборке падает имя
недостающего файла.

Голая рука (`hand.png`) кладётся последней: пальцы держат предмет из слота `hand`,
поэтому должны быть перед ним. Если в руке ничего нет, слой не рисуется вовсе —
спрайт это отдельная кисть, а не конец руки, и на `body.png` рук не нарисовано,
так что пустая рука выглядит именно как пустая, без культи.

Миниатюры в карточках — кроп общего листа через `background-position` в процентах,
а не в пикселях: пять миниатюр фиксированного размера с зазорами не влезают в
320 pt, карточки должны уметь сжиматься.

Куплённое и надетое хранит сервер; в `localStorage` (`brokerstars.owned`,
`brokerstars.outfit`) лежит копия с теми же try/catch. Покупка идёт на сервер, и
он же решает, та ли это ступень и хватило ли монет, — «Комната и гардероб на
сервере» ниже.

## Тесты

`npm test` (vitest, 659 тестов в 38 файлах). Покрыта симуляция (`src/sim/*.test.ts`) — то, что
в ТЗ названо единственным жёстким требованием, — ворота лиг
(`src/ui/leagues.test.ts`): лестница открывается ровно на последней недостающей
победе, ступень не перепрыгивается, награда растёт снизу вверх, у каждой лиги
свой соперник из `CONFIG.bot`, — и сглаживание оси графика
(`src/ui/chart.test.ts`): расширение мгновенное, сужение плавное, видимая точка
не прячется ни при каком времени кадра. Последнее нашло дыру: `NaN` в дельте
времени отравлял домен и гасил график до конца матча.

По симуляции:

- **детерминизм** — один сид даёт тик в тик тот же рынок, разные сиды дают разный,
  и повтор той же последовательности сделок приводит к тому же состоянию;
- **жизненный цикл матча** — ровно 160 тиков и остановка, автозакрытие позиций по
  цене последнего тика не меняет нетворт, победа у того, кто дороже, сдача отдаёт
  матч сопернику, банкротство обнуляет позиции;
- **торговля** — сделка списывает деньги и комиссию, slippage всегда против
  трейдера, шорт зачисляет выручку, средняя цена входа усредняется, закрыть
  позицию можно и без денег, знак реализованного P&L верен в обе стороны;
- **влияние на рынок** — сделка двигает цену и затухает по `decayPerTick`, с
  выключенным флагом не двигает;
- **рынок** — сегменты покрывают матч без разрывов, у флэта нет силы, новостной
  сегмент всегда силы 3 и попадает в квартал, который его заказывал, цена не
  выходит из клампа `[base*0.2, base*4]`, фазы идут по порядку и с флагом
  `phases: false` схлопываются в нейтральную;
- **кварталы** — матч режется на четыре равных отрезка, закрывающий тик
  принадлежит последнему кварталу, полугодие идёт от 0 на открытии до 1 на
  закрытии и начинается заново со второго;
- **компании и свойства** (`src/sim/companies.test.ts`) — раздача всегда даёт три
  разные компании только из пула лиги, всегда с одной базовой и без двух линий
  одного цветового семейства; каждое свойство проверено на ленте отдельно, и
  соседние обычные компании печатают ровно те же цены, что и без него;
- **выключение любого флага** не ломает матч;
- **перки трейдера** (`src/sim/perks.test.ts`) — скидка достаётся только тому,
  кому положена, и не двигает ленту; закрытие по средней и slippage считаются
  как обещано; порог банкротства и пол по результату работают; стоп срабатывает
  ровно столько раз, сколько разрешено; возврат первого убытка — один; отмена
  сделки восстанавливает книгу точно, предлагается один раз, закрывается по
  истечении окна и не ломает детерминизм матча;
- **одежда в перки** (`src/ui/perks.test.ts`) — голый трейдер получает ровно те
  условия, что были в игре до одежды; каждая лестница растёт в нужную сторону;
  слоты не гасят друг друга; проценты на карточках совпадают с применяемыми.

Симуляцией дело давно не ограничивается. Из 38 файлов 11 лежат в `worker/test/` и
проверяют вторую половину — подпись и сессии (`auth`), выдачу наград, ключ
сортировки обеих таблиц (`board`), ответы бота, кулдаун зова в чат, корпорации,
удаление аккаунта одной пачкой, лимиты обратной связи, оплату приведённого друга,
покупки и день в профиле, идемпотентность сдачи результата (`verify`).

Остальное — **провод**. У каждого `protocol.ts` свой тест, и он проверяет ровно
то, о чём обе стороны договорились: откат суток и раздачу заданий (`daily`),
бросок полки и веса редкостей (`shop`), блуждание цены и арифметику портфеля
(`market`), форму сейва и переезд старого (`profile`), коды друзей, дуэлей и
связывания, имя и сезон корпорации, длины сообщения обратной связи. Плюс то, что
обещано игроку на экране: `i18n.test.ts` падает на пропущенном id и на лишнем,
`tutorial.test.ts` держит те четыре вещи, без которых тур не тур,
`ui/api.test.ts` — очередь недосланных матчей, `ui/line.test.ts` — часы линии в
дуэли, `duel/snapshot.test.ts` играет настоящий матч и сверяет зеркало тик в тик.

Тесты проверены мутациями: перевёрнутый знак slippage роняет 3 теста, разрыв в
расписании сегментов — 2, сдача в пользу сдавшегося — 1.

## Структура

Файлы `*/protocol.ts` — это провод: форма, на которую игра и сервер согласились,
в одном файле, который импортируют обе стороны. Их девять, и лежат они рядом с
`sim/`, а не внутри `ui/`, ровно потому, что принадлежат не экрану.

```
src/
  main.tsx      точка входа: платформа, язык, первый кадр
  sim/          чистый TS, ничего не знает о React
    config.ts   ВСЕ числа баланса, один объект CONFIG
    companies.ts реестр компаний, их свойства и раздача на матч
    traits.ts   что свойство компании делает с ценой на каждом тике
    perks.ts    условия, на которых торгует конкретный трейдер
    abilities.ts пять абилок шеи: эффект, цель, запреты — и ни одного броска
    rng.ts      mulberry32 + gauss, seeded
    market.ts   расписание сегментов, шаг цены, кварталы, фазы, новости
    trading.ts  исполнение, slippage, комиссия, impact, TRADE_FRACTION
    bot.ts      ИИ — читает график и ходит через тот же applyAction, что и игрок
    match.ts    createMatch(seed, cfg) / step(state) / runToEnd(state)
    types.ts    состояние матча
  platform/     где игра запущена и всё, что этот ответ меняет
    index.ts    интерфейс Platform и выбор одной из трёх реализаций
    telegram.ts мини-апп: подпись, initData, шторка «поделиться», haptics
    android.ts  Capacitor-WebView: вход через Google, сессия воркера, интент
    web.ts      обычная вкладка: никто не подписан и никто не назван
  duel/         формат провода между игрой и сервером дуэли
    protocol.ts какие бывают сообщения и что в них лежит
    snapshot.ts состояние матча, записанное для одного из двух глаз
  friends/      формат провода для списка друзей
    protocol.ts код друга, строка списка, награда за приведённого
  corp/         формат провода для корпораций
    protocol.ts имя и алфавит, сезон, среднее вместо суммы, виды событий ленты
    emblems.ts  знаки и десять цветов: закрытый каталог, он же проверка
  profile/      формат провода между игрой и её сохранением на сервере
    protocol.ts комната, шкаф и монеты: форма, проверки, переезд старого сейва
  shop/         полка магазина на сутки
    protocol.ts пять вещей в день, веса редкостей, почему бросок хранится
  daily/        день: что такое сутки, бонус за них и задания на них
    protocol.ts DAILY_BONUS, каталог заданий, откат суток, чистка с провода
  market/       стойка акций: цена компании на сутки и что игрок держит
    protocol.ts блуждание цены, портфель, покупка/продажа, спред
  awards/       что есть на полке, одинаково для игры и сервера
    catalogue.ts список наград: id, открытая или скрытая, пороги
  link/         связывание двух входов в одного игрока
    protocol.ts код на восемь символов, десять минут, направление связи
  feedback/     что игрок вправе прислать разработчикам
    protocol.ts длины и пауза между сообщениями — одинаково у обоих концов
  ui/           React, только отображение
    App.tsx     все экраны, переходы между ними и петля матча
    Menu.tsx    комната, герой, две рельсы и колонка из четырёх
    i18n.ts     обстановка экранов на двух языках и выбор языка
    tutorial.ts шесть шагов тура: метки в разметке и порядок
    TutorialOverlay.tsx подсветка метки и затемнение всего остального
    chart.ts    отрисовка графика и графика нетворта (без React)
    line.ts     часы линии в дуэли: тики приходят неровно, линия едет ровно
```

## Кварталы и компании

Матч — это финансовый год: четыре квартала по 20 секунд, два полугодия по 40.
Границы нарисованы на графике пунктиром с подписями Q1—Q4, и в `CONFIG.phases`
теперь по одной фазе на квартал: волатильность растёт от 0.7 к 1.6, а два
новостных события разнесены по одному в Q2 и Q3, вместо двух подряд в одной
сорокасекундной фазе. Всё это считается из `CONFIG.match.quarters` — число 4
нигде не зашито, только читается оттуда.

Компаний в игре 28, и на матч раздаются три из них. Пул зависит от лиги: восемь
базовых компаний доступны везде, и каждая ступень лестницы добавляет ещё пять
своих.

**Розданная тройка держится, пока матч не сыгран.** Лига запоминает сид, которым
она раздала доску (`loadHeld` / `saveHeld` в `ui/board.ts`, ключ на лигу), и
отдаёт ту же тройку, пока эту доску не доиграют до свистка. Иначе выход с экрана
доски и вход обратно раздавал новые три компании — и то же самое делал заход в
соседнюю лигу и назад. Это бесплатный реролл, а бесплатный реролл — это ровно то,
за что продаются BALL CAP и BLACK BRIM: игрок уже имел даром то, что стоит 7 и 20
монет. Сид лежит в сторадже, а не в памяти, иначе перезагрузка страницы была бы
тем же рероллом на один шаг длиннее.

Сдача матча доску **не** освобождает и компании в каталог **не** записывает: сдаться
— это не сыграть, и иначе surrender стал бы тем же рероллом, только на четыре тапа
медленнее. Поменять доску, которая не нравится, можно рероллом — за него и платят. Бронза раздаёт 30 разных досок, корона — 702, так что состав почти не
повторяется. Одно место в раздаче всегда
занимает базовая компания — на её фоне читаются две странные, — и две линии
одного цветового семейства на график не попадут. Раздача идёт от сида матча, так
что повтор сида возвращает и те же цены, и тот же состав.

Свойство компании (`trait`) — одно из одиннадцати; это либо форма расписания
сегментов (`buildSchedule`), либо вмешательство в шаг цены через `TickPlan`
(`src/sim/traits.ts`). У свойств собственный поток RNG, поэтому добавление
странной компании на доску не сдвигает цены обычных ни на тик.

### Цвета компаний

Цвет компании — это её линия на графике, и три линии в матче должны читаться как
три разные вещи. Правило «две компании одного цветового семейства на доску не
попадут» этого не обеспечивало: семейства сами были расставлены по кругу
неровно. Четыре из девяти (`teal`, `cyan`, `blue`, `silver`) сидели в 120
градусах сине-зелёного угла, `silver` был бледно-голубым, то есть фоном панели,
а `CRAMPON STEEL` числился зелёным при тоне 145°, то есть на деле был бирюзовым
и сливался с `EMBER UTILITIES`. Внутри семейства компании различались сдвигом
тона на 1–9°, а не светлотой.

Мерка — CIEDE2000 (ΔE): ниже 10 два цвета читаются как один, от 25 — как явно
разные. Замерено по всем парам в пуле каждой лиги:

| Лига | Худшая пара на одной доске | Худшая пара вообще | Ближайший к фону панели |
|---|---|---|---|
| 0 | 17.9 → **28.9** | 17.9 → **28.9** | 40 → 36 |
| 1 | 17.9 → **21.0** | 3.3 → **8.8** | 34 → 36 |
| 2 | 9.2 → **19.4** | 3.1 → **8.8** | 27 → 36 |
| 3 | 9.2 → **19.4** | 3.1 → **8.8** | 27 → 36 |
| 4 | 9.2 → **19.4** | 1.6 → **8.6** | 27 → 36 |

Палитра подобрана отжигом в пространстве LCh (светлота / насыщенность / тон),
в два прохода. Сначала расставляются восемь базовых компаний и только они: они
на доске в каждой лиге, поэтому их взаимная разнесённость — это и есть то, что
получает первая лига, а первая лига у каждого игрока первая. Потом вокруг них,
не двигая их, размещаются остальные двадцать. Тон каждой компании заперт в
полосе своего семейства, так что зелёное осталось зелёным; полосы разведены по
кругу с зазорами, и `silver` уведён в тёплый нейтральный — холодный нейтральный
и есть та самая бледно-голубая линия, от которой мы уходим.

Три пары чисел выше зафиксированы тестами в `companies.test.ts` (порог 18 для
пар, способных попасть на одну доску, 7 для пар внутри семейства, 30 до фона
графика) — палитру нельзя молча испортить правкой одного хекса.

Полностью развести всё не выйдет и не нужно: семейств девять, а компаний 28,
поэтому внутри семейства цвета остаются близкими (ΔE ~9). Это осознанный
размен — две компании одного семейства никогда не попадают на один график,
только в списки, где рядом с цветом есть логотип и название.

Сам список компаний и то, что делает каждая, здесь намеренно не расписан: это
то, что игрок открывает сам. Кнопка `MARKET` в меню ведёт на рынок, куда
компания попадает, **когда матч с ней доигран до свистка** — не когда её раздали
и не когда её увидели на экране старта. Раньше запись шла в момент раздачи, и
щёлкнуть в экран матча и обратно хватало, чтобы собрать весь ростер, не сыграв ни
одной партии. Сдача не считается по той же причине. Данные — в
`src/sim/companies.ts`, встреченные игроком лежат в профиле на сервере (`seen`),
а в `localStorage` под `brokerstars.companies` остаётся копия для первого кадра.

**Экран назывался АРХИВ и называется РЫНОК.** На нём лежат компании и стойка, где
покупаются их акции; и то и другое — рынок, а слово «архив» не называло ни того,
ни другого. Переехали только строки: компонент, файл и классы `arch-*` остались
со старым именем, потому что игроку их не видно, а переименование секции стилей
ради одной кнопки — это большой диф, который умеет только вносить ошибки. Обе
причины записаны в шапке `src/ui/ArchiveScreen.tsx`, ровно как `players.stars`
носит свою.

Вкладок на рынке две — **компании** и **портфель**, — и это те самые две вещи, по
которым он назван. Рейтинг был когда-то третьей и уехал на отдельный экран из
меню: то единственное в игре, где есть другие люди, не должно лежать в двух
нажатиях за полкой с компаниями. Награды были третьей после него и уехали в
профиль: они про игрока, а не про мир, и рядом с ценами акций были здесь
единственным, что не про рынок.

## Профиль

Правая рельса меню, одна кнопка (`src/ui/ProfileScreen.tsx`). Всё, что на этом
экране лежит, игра считала и раньше — и жило это по местам, которые про другое.
Награды стояли на рынке рядом с ценами акций, то есть на экране про мир, а не про
игрока. Друзья были круглой кнопкой на рельсе. А карьеры не было нигде вовсе:
сервер с самой первой сборки считает победы по лигам, победы в дуэлях, лучшую
книгу и высшую взятую лигу — и ни одно из этих чисел никогда не показывалось в
одном месте.

**Чем он не является.** Не хабом с копией каждого экрана. На нём три вещи,
которые верны про **игрока**, — что на нём надето, что он сделал и кого знает, —
а всё остальное из меню остаётся там, где стояло.

Сверху сам трейдер в том, что на нём сейчас, и имя под ним: это единственная
картинка в игре, которая ничья больше, и единственный экран, где он — предмет
разговора, а не декорация. Ниже шесть чисел:

| Поле | Что это |
|---|---|
| ПОБЕД | сумма `wins` по всем лигам, то есть победы над ботами и только они |
| ПОБЕД В ДУЭЛЯХ | отдельным числом, потому что лестница дуэли не считает |
| ЛУЧШИЙ КАПИТАЛ | `bestNetWorth`, лучшая книга за всё время |
| ВЫСШАЯ ЛИГА | `topLeague`, именем лиги, а не индексом |
| МОНЕТ ЗАРАБОТАНО | `earned` — то, по чему ранжирует таблица |
| ВСТРЕЧЕНО КОМПАНИЙ | сколько из 28 попало в каталог |

Победы над ботами и победы в дуэлях сложить в одно число было бы удобно и
неправильно: друг, готовый проиграть десять раз, — не подъём, ровно поэтому
лестница дуэли и не считает, и экран, который тихо складывал бы их обратно,
отменял бы это решение обратно.

**Числа — серверные.** Каждое приходит из профиля, который отдаёт воркер
(`src/profile/protocol.ts`), по той же причине, по какой там же считаются монеты:
клиент, считающий свои победы, — это клиент, который умеет их править.

Под числами одна строка с людьми и проход внутрь: весь экран друзей — список,
ссылка, код — лежит за ней, потому что туда **идут что-то сделать**, а здесь
смотрят, есть ли вообще кто-нибудь. Число на строке спрашивается самим этим
экраном, а не передаётся сверху: это один запрос за одним числом, и делает его
тот экран, который число рисует. Пока не ответили — и навсегда в сборке без
сервера — на строке стоит фраза, а не «в списке: 0», потому что ноль про
непрочитанный список это неправда.

`BACK` с экрана друзей возвращает на профиль даже тогда, когда друзей открыла
ссылка-приглашение: один предсказуемый выход лучше, чем память о том, какой
дверью вошли.

Полка наград переехала сюда целиком, файлом (`AwardsShelf.tsx`), без единой
изменённой строки: переезд на тысячу пикселей не обязан быть ещё и переписыванием.

## Награды

Двадцать штук, в профиле, под заголовком НАГРАДЫ (`src/ui/AwardsShelf.tsx`).
Четырнадцать открыты — это цели, а цель, которой не видно, не цель. Шесть скрыты
и показаны одной строкой «ЕЩЁ N НЕ НАЙДЕНО»: скрытая награда — это не более
трудная версия открытой, а то, что с тобой случилось, и напечатанное условие
превратило бы каждую в задание.

**Считает сервер** (`worker/src/awards.ts`), по той же причине, по которой он
считает монеты и победы: награда, которую браузер выдал себе сам, — это строчка в
`localStorage`, и в данном случае строчка, утверждающая, что ты обыграл десять
человек. И только так она переживает новый телефон.

**Раз выдано — не отбирается.** Половина условий читается с состояния, которое
умеет ехать назад: разработчик вернул шляпу — и «ОДЕТ» испарился бы. `grant`
только добавляет; награда, которая гаснет, — не награда, а лампочка.

**Судится в момент, а не по истории.** Матчевые условия смотрят на матч, который
только что кончился, а не сканируют таблицу `results`, так что ни один запрос не
растёт вместе с ней. Двум наградам нужна память — победы в дуэлях и текущая
серия, — и она лежит счётчиками в профиле по той же причине.

Пороги подобраны не по круглым числам, а по тому, что реально происходит. На
первых 45 матчах живых людей: 20 000 брали в 18% матчей, 30 000 — в 4%, 50 000 —
в тех же 4% (оба раза один и тот же человек в свои два хороших дня), 75 000 не
брал никто. Верхняя ступень — горизонт, а не рутина, и она сама поедет ближе,
когда люди оденутся: одежда делает торговлю дешевле.

Названия четырёх наград за лиги берутся **из самих лиг**, а не пишутся второй
раз. Иначе первое же переименование лиги разъедется с наградой — ровно так одна
из них успела назвать бронзовую лигу «ямой», хотя по-русски игра этого слова
никогда не использовала.

Ничьей среди наград нет намеренно. Против бота её не случилось ни разу за 45
матчей и, скорее всего, не может: победитель определяется сравнением дробных
чисел. А в дуэли она не редкость и не достижение — двое, которые просто стоят,
заканчивают на одном и том же круглом числе. Именно это и произошло в первой же
дуэли, сыгранной в тесте от начала до конца.

## День: доллары, бонус и задания

Левая рельса меню, круглая кнопка с портфелем. За ней — экран дня:
сверху **ежедневный бонус**, под ним три задания на сегодня. Кнопка **светится
золотом**, пока за ней что-то лежит: не забран бонус или выполнено задание, за
которое ещё не заплатили (`worthATap` в `src/daily/protocol.ts`). Это
единственная причина, по которой кнопка, ведущая на экран без нового содержимого,
вообще стоит на главном.

**Доллары — вторая валюта, и она отдельная намеренно.** Монеты зарабатываются
игрой и тратятся на комнату и шкаф; всё, что покупается за монету, делает
следующий матч лучше. Доллары — для другой половины игры, метагеймовой покупки
акций компаний, и если бы они были одним кошельком, каждая покупка там была бы
покупкой, не сделанной в магазине. Поэтому: своя валюта, свой способ заработка
(прийти, а не выиграть), и магазин их не видит вовсе.

В отличие от монет, доллары — это **одна колонка, а не три**. Тройка
`stars`/`granted`/`spent` существует потому, что `players.stars` — это рейтинг,
который не имеет права уменьшаться от траты. Долларами никто не ранжируется, и
делить одно число на три было бы копированием сложности, а не осторожностью.

**Сутки — это `Math.floor(now / 86400000)`**, целые UTC-сутки от эпохи, и считает
их сервер. Не местные сутки, намеренно: игрок, перелетевший на восток, иначе брал
бы два бонуса за один вечер, а перелетевший на запад ждал бы лишнее. Откат суток
— не задача, которая где-то крутится: день просто перестаёт совпадать, и всё, что
под ним лежало, выбрасывается на ближайшем чтении строки (`read` в
`worker/src/profile.ts`). Игрок, не заходивший месяц, не стоит ничего.

**Бонус — 500 долларов, `POST /profile/daily` с `{claim: 'bonus'}`.** Решает
сервер, по той же причине, по которой он решает выплату за матч: браузер, который
говорит, что уже завтра, — это браузер, который просит ещё одну выплату. Второй
тап получает отказ и профиль как он есть, а не вторые пятьсот; токен тут не
нужен, в отличие от сдачи матча, — операция идемпотентна сама по себе, потому что
вторая попытка находит `bonus` уже поднятым. Игра при этом рисует выплату сразу и
принимает то, что вернулось, — как и всякая покупка.

`DAILY_BONUS` — единственное место, где эта сумма записана, и она же задаёт темп
стойки акций: при 500 в день и ценах компаний от 200 до 2600 новичок берёт одну
акцию в первый вечер и за пару недель собирает портфель на несколько тысяч.

**Задания платят монетами. Три штуки в день, и каждый день другие.** Восемь
штук в каталоге, три раздаются на день, и раздаёт их **сам день**: `questsFor(day)`
считает тройку из даты, а не хранит её. Отсюда всё остальное — колонки с выбором
нет, момента «раздать задания» нет, для не заходившего игрока писать нечего, и
экран с сервером не могут смотреть на разные задания. Это та же сделка, что у
`createMatch(seed)`: одно число на входе — один и тот же мир на выходе.

У каждого задания есть **вид** того, что оно считает (`counts`), и двух заданий
одного вида в одном дне не бывает. Иначе шаффл мог бы выдать «сыграй три» рядом с
«сыграй пять» и назвать это работой на день; а так день всегда просит три разных
вечера. Виды: матчи, победы, планка по прибыли, сделки, лучший капитал за матч,
матчи без банкротства, дуэли, победы в дуэлях.

| задание | считает | цель | монет |
|---|---|---|---|
| ПРИЙТИ | матчи | 3 | 2 |
| ДОЛГИЙ ВЕЧЕР | матчи | 5 | 3 |
| ВЗЯТЬ СВОЁ | победы | 1 | 2 |
| ВЗЯТЬ ДВАЖДЫ | победы | 2 | 3 |
| ХОРОШО ПОТОРГОВАТЬ | планка по прибыли | 1 | 2 |
| БЕЗ ПЕРЕРЫВА | сделки | 20 | 2 |
| ХОРОШИЙ ВЕЧЕР | лучший капитал | 15 000 | 3 |
| НА НОГАХ | матчи без банкротства | 3 | 2 |
| ПОЗВАТЬ ДРУГА | дуэли | 1 | 3 · нужен друг |
| РАЗОБРАТЬСЯ | победы в дуэлях | 1 | 4 · нужен друг |

День выходит на 6–10 монет — примерно один хороший матч в серебряном зале. Так и
задумано: обойти задания стоит нажатий, но до магазина всё равно быстрее доиграть,
чем дозайти.

**Два задания на дуэль и правило вокруг них.** Дуэль — единственное, что игрок не
может сделать в одиночку, поэтому она обложена двумя ограничениями. В одном дне
такое задание может быть **только одно**: две другие ячейки всегда остаются тем,
что делается одному. И день вообще спрашивает про дуэль **примерно раз в три дня**
— это `SOCIAL_DAYS`, одно число, которое и надо крутить, если тянет слишком сильно
или слишком слабо. Отдано отдельному броску до шаффла намеренно: сам по себе
шаффл ставил дуэль перед человеком в 55% дней, а это уже не приглашение поиграть с
другом, а налог на то, что друга нет под рукой.

Дуэльное задание попадает в **первую** ячейку и читается на экране первым. То, что
надо не просто сыграть, а сначала организовать, должно попадаться на глаза раньше
остального. Платят они на монету больше, чем стоят по трудности: дуэль — те же
восемьдесят секунд, работа в том, чтобы её собрать, и лишняя монета именно за это.
«ПОЗВАТЬ ДРУГА» засчитывает и проигранную дуэль.

**Чего в каталоге нет намеренно.** Ничего с воротами по лестнице — «сыграй в
серебряном зале» невыполнимо для того, кто его не открыл, а это ровно тот игрок,
для кого дейлики и придуманы. И ничего про каталог компаний: ветеран, встретивший
все, не смог бы выполнить такое больше никогда. Обе двери закрыты для целого
класса игроков навсегда, и этим отличаются от дуэли, где дверь открывается, как
только кто-то ответил.

**Кто считает.** Сервер, в `settle` — там же, где лестница и полка
(`worker/src/profile.ts`). Дуэль **считается дважды**: и как обычный сыгранный
матч, и в счёт тех двух заданий, которые её и просят. Лестница дуэли игнорирует —
друг, готовый десять раз проиграть, это лифт, а не подъём, — но здесь инфлировать
нечего. Сдавшийся матч не считается
вообще: игра его не отправляет, поэтому сервер о нём не знает — иначе «сыграй три
матча» было бы тремя нажатиями СДАТЬСЯ. Игра ведёт свою копию тем же `countMatch`,
чтобы экран был прав до ответа сети и вообще работал в сборке без сервера.

`best` («лучший капитал») — единственный вид, который берёт максимум, а не сумму:
закончить матч с 15 000 — это не «трижды подержать по 5 000».

**Забирать надо руками.** Выполненное задание становится золотым и превращает свою
полоску в кнопку ЗАБРАТЬ; пока её не нажали, кнопка дня на главном экране горит.
Монеты падают в `granted`, а не в `players.stars`: таблица ранжирует то, как
человек играет, и двух игроков с одинаковыми матчами не должно разделять то, кто
из них не забыл нажать кнопку. Тратятся они в магазине как любые другие.

**Ничего из этого не переезжает со старого сейва.** `claim` долларов не несёт и
не понесёт: долларов не существовало до того, как появилась колонка, так что
предъявить их неоткуда, а валюта, которую клиенту разрешено заявить, — это
валюта, которую печатает консоль.

## Акции: стойка на рынке

Второй половине игры доллары и предназначались. Монеты покупают шляпу, доллары —
**кусок компании**, против которой ты уже играл. Стойка живёт там же, где обзор
компаний, — на РЫНКЕ, и это те самые две вещи, по которым экран назван. Вкладка
**КОМПАНИИ** — под карточкой компании цена на сегодня, изменение со вчера, график
за две недели и две кнопки; вкладка **ПОРТФЕЛЬ** — что держишь, почём взял и что
оно сделало за ночь.

**Покупать можно только встреченное.** Компания, которой не было ни на одной
доске, на рынке заперта — и купить её нельзя тоже (`trade` в
`worker/src/profile.ts`). Это то самое, что привязывает стойку к игре, а не
ставит её рядом: чтобы вложиться в KRAKEN CHEM, надо сначала против него
поторговать.

### Откуда берётся цена

**Одна цена на сутки**, те же UTC-сутки, что и у бонуса, и меняется она ровно в ту
же полночь. Поэтому «купи сегодня — зайди завтра» это буквально цикл, а часы в
игре одни, а не двое.

**Таблицы цен нет нигде.** Ни колонки, ни задачи, которая крутится в полночь.
Цена **вычисляется** из компании и дня — та же сделка, что у `questsFor(day)` и у
`createMatch(seed)`: одно число на входе, один и тот же мир на выходе. Игрок, не
заходивший полгода, не стоит ничего, а клиент с сервером физически не могут
смотреть на разные котировки.

Цена — **блуждание в логарифмах**, свёрнутое по **скользящему окну в 400 дней** от
цены размещения компании:

```
x = 0                                    # отклонение от базовой цены, в логах
для d от (day − 400) до day:
    rng  = Rng(hash(salt | id | d))
    x   += дрейф(характер компании)
    x   += rng.gauss(sigma)              # шок дня
    x   -= 0.02 · x                      # тяга домой
    x    = clamp(±0.18)                  # не больше ~20% за сутки
цена = base · exp(clamp(x, ±1.6))
```

**Окно, а не эпоха** — потому что свёртка от фиксированной даты дорожает на шаг
каждые сутки, навсегда. Окно фиксированной длины стоит одинаково всегда, а шва на
его краю не видно: возврат к среднему за 400 дней гасит вклад самого старого дня
до трёх десятитысячных. Ряд при этом **самосогласован**: серия длины N якорится на
`400 + N` дней назад, поэтому каждый её элемент — ровно то же число, что
однодневный ответ на ту дату. «Вчерашняя цена» на графике и цена, по которой
вчера прошла сделка, — одно и то же (это проверяется в `src/market/protocol.test.ts`).

**Волатильность берётся из самой компании**: `sigma = noiseSigma · 4`. Новых
данных в реестр не добавлено ни одного — кто дёргается в матче, дёргается и в
портфеле. URANUS ходит около 6% в день, HOMESTEAD MUTUAL — около 1.7%.

### Характер компании работает и здесь

`traits.ts` говорит, что причуда делает с ценой на тике; стойка делает то же
самое с шагом в сутки. Поэтому тэглайн, который рынок и так печатает, — это
лучший совет, какой игрок вообще получит:

| причуда | в портфеле |
|---|---|
| STATE (`regulated`) | тяга домой ×5, шок ×0.6 — облигация доски |
| TREND (`locked`) | шок сохраняет вчерашнее направление в 7 случаях из 10 |
| BUBBLE | дрейф +0.9% в день и 1.5% шанс схлопнуться до 40% |
| SHOT (`moonshot`) | −0.15% в день, но 0.7% шанс прыжка ×1.9 |
| FLOOR | ниже своего пола не печатается никогда |
| DIV (`dividend`) | шок ×0.7 — тихая бумага |
| NEWS (`headline`) | 12% шанс, что день идёт тройным шоком |
| LUXURY | шок ×0.5, но 1.5% шанс дня на −40% |
| STALLS | 25% дней вообще без движения |
| HOLDS (`ratchet`) | скользящий пол: не ниже `giveBack` от своего максимума |

За год это выглядит так: YETI COIN и TULIP EXCHANGE отдают по −61% за один день и
не восстанавливаются, VELVET CROWN и OBSIDIAN CLUB роняют по −40% на ровном месте,
а CIVIC ANCHOR за 365 дней не уходит от своих 500 дальше чем на четверть.

### Правила торговли

- Целые акции, без плеча и без шорта. Продавать можно — иначе доллары были бы
  сливом в одну сторону и прибыль нельзя было бы забрать.
- **Заявок в сутки сколько угодно.** Три в день были задуманы так, чтобы позиция
  была решением, а не привычкой, — а делали они то, что доллары оставались
  непотраченными: бонус платит каждый день, баланс растёт, и то, на что его
  копят, закрывается на третьей заявке. Держать эту линию нечему и не надо: спред
  берётся с обеих сторон каждой заявки, поэтому перекладывание — способ терять
  деньги, а не зарабатывать, и цена двигается раз в сутки для всех, так что
  внутри одного дня торговать не против чего. Лимит никогда не был тем, что
  мешало играть стойкой в обе стороны, — этим были и остаются спред и одна цена
  на день. Снят совсем, а не поднят: потолок в тридцать — то же правило с менее
  честным числом, и экранам всё равно пришлось бы что-то отсчитывать.
  `Daily.orders` уехал вместе с ним, а строка сейва, которая его ещё несёт,
  просто игнорируется на входе.
- **Спред 1%** в каждую сторону: купить дороже, продать дешевле. Чтобы
  ежедневное перекладывание стоило хоть чего-то.
- Себестоимость — средняя: при продаже части позиции из `cost` уходит ровно та же
  доля, что и акций, так что «взял по 512» остаётся правдой про остаток.
- «За ночь» на вкладке ПОРТФЕЛЬ — это, по каждой позиции, **движение цены со
  вчера, умноженное на число акций**. Позиция, **тронутая сегодня**, в это число
  не входит вообще: она куплена по сегодняшней цене, значит скачок со вчера
  случился без игрока. Иначе тот, кто купил утром, получал бы прибыль за ночь,
  проведённую с долларами в кармане, — и получал бы её каждый раз, когда цена
  оказалась выше. Это была бы не биржа, а автомат, который платит за вход.
  Поэтому покупка входит с нулём и начинает считаться завтра — в интерфейсе такая
  строка помечена «СДЕЛКА СЕГОДНЯ», чтобы ноль не выглядел ошибкой.

### Кто считает и почему клиенту не дают формулу

Блуждание детерминировано, значит всякий, кто открыл бандл, посчитал бы цену
**завтрашнего** дня и купил победителя. Поэтому сид **солится**: `MARKET_SALT` —
секрет воркера (`wrangler secret put MARKET_SALT`), и он оттуда не выходит.
Браузеру присылают **цены**, а не способ их получить: `GET /market` отдаёт
последние 14 дней по каждой компании, один и тот же ответ для всех, без подписи и
без чьей-либо личности — потому и кэшируется.

Сделка идёт через `POST /profile/trade` с `{company, shares, sell}`, и **больше из
тела не читается ничего**: какой сегодня день, сколько стоит акция, сколько заявок
осталось и встречал ли игрок эту компанию — всё решается на той стороне. Отказ
приходит двухсоткой с профилем как он есть, как и всякий отказ здесь: клиенту,
у которого устаревшая картина мира, нужна свежая, а не код ошибки.

**Сборка без сервера** считает своё блуждание с пустой солью (`localMarket` в
`src/ui/market.ts`) — котировки не те, по которым что-то settle'ится, но стойка
работает в `npm run dev` и в обычном браузере. Та же сделка, что у ежедневного
бонуса, и она честнее, чем кнопка, которая ничего не делает.

**Со старого сейва не переезжает ничего.** `claim` не несёт ни долларов, ни
портфеля: валюта, которую клиенту разрешено заявить, — это валюта, которую
печатает консоль, а купленные на неё акции — то же самое на шаг дальше.

## Рейтинг и сервер

Рейтинг — экран из главного меню, и в нём **две вкладки**.

**МОНЕТЫ** ранжируют заработанное, `players.stars`. Это число только растёт:
трата в магазине не должна стоить места, потому что таблица — запись о том, как
человек играет.

**ДОЛЛАРЫ** ранжируют стойку акций, и ключ там — **не баланс долларов**. Таблица
балансов ранжировала бы за то, что человек ничего не купил: в момент покупки
баланс падает, и месяц просидевший на бонусах возглавил бы таблицу про биржу.
Поэтому ключ — наличные плюс акции по сегодняшней цене: тот самый мета-капитал,
который игрок и так видит про себя на вкладке ПОРТФЕЛЬ. Строка показывает, из
чего капитал состоит («12 400 в акциях» против «всё в наличных»), потому что это
и есть вся история о том, как человек до него дошёл.

Две таблицы стоят рядом именно потому, что поощряют противоположные привычки:
монетная только растёт и говорит о заработанном, долларовая живая — место можно
потерять за ночь из-за упавшей компании. Как это считается и почему ключ нельзя
выразить в SQL — `worker/src/board.ts` и `worker/README.md`.

`worker/` — Cloudflare Worker с базой D1, за которым живёт таблица игроков во
вкладке РЕЙТИНГ. Подробности и команды развёртывания — в `worker/README.md`.

Игра до сих пор целиком лежала у игрока в браузере, и `src/ui/admin.ts` прямо
писал, что всё, чего нельзя подделать, требует сервера, «которого у этого
прототипа нет». Теперь он есть, и делает ровно две вещи, которые клиенту
доверить нельзя.

**Оба конца выкатываются из одного коммита.** `deploy.yml` собирает клиент на
Pages, `worker.yml` заливает воркер в Cloudflare — оба по пушу в `main`. Раньше
второе делалось руками, и в зазоре между ними жил целый класс багов: бандл,
знающий про маршрут, которого на сервере ещё нет. Что нужно завести в репозитории
и почему миграции туда не входят — `worker/README.md`.

**Кто прислал.** `initDataUnsafe` не подписан ничем. А `initData` подписан
HMAC-SHA256 по бот-токену, и воркер этот токен держит, поэтому отличает игрока
из Telegram от `curl`. Без валидной подписи не пишется ничего: `/result`
отвечает 401, а без заданного `BOT_TOKEN` — 503 на всё подряд. Отказ закрытый
намеренно.

**Сколько это стоило.** Клиент не сообщает, сколько монет заработал. Он
сообщает, что произошло — лига, исход, взят ли порог прибыли, — а сумму воркер
берёт из **своей** копии таблицы наград. Число подделать нельзя; соврать можно
только про исход матча, и на это заготовлена перепроверка реплеем: матчи
детерминированы по сиду, таблица `results` уже хранит сид и лигу, и колонка
`verified` ждёт того, кто прогонит симуляцию на сервере.

Ранжирование идёт по **заработанным** монетам, а не по текущему балансу:
потратить их в магазине — это выбор, и он не должен стоить места в таблице.

**Матч засчитывается один раз, и поэтому отправку можно повторить.** С
результатом уходит токен — имя этого матча, выданное один раз, когда он
кончился. Первый приход платит, каждый следующий с тем же токеном получает тот
же ответ и ничего не добавляет; держит это `UNIQUE` на колонке, а не проверка в
коде. Нужно это вот зачем: баланс теперь считает сервер, поэтому отправка, у
которой оборвалась сеть, стоила бы игроку монет за сыгранный матч. Раньше выбор
был между «потерять их» и «заплатить дважды» — таймаут выглядит одинаково в обоих
случаях, — а теперь его нет: игра кладёт непрошедший матч в очередь
(`brokerstars.pending`) и досылает при следующем открытии, до того как спросит
профиль. Отказ, который не изменится (400, 401, 403), в очередь не попадает,
чтобы она не стала местом, которое никогда не пустеет.

Клиентская сторона — `src/ui/api.ts`, и она вся необязательная. Нет
`VITE_API_URL` (любая локальная сборка), нет `initData` (игра открыта в обычном
браузере, а не в Telegram) — отправка молча пропускается, а вкладка говорит об
этом словами вместо бесконечного колёсика. Матч играется и монеты начисляются
локально в любом случае: таблица — это витрина, а не условие игры.

## Комната и гардероб на сервере

Комната, шкаф и баланс монет лежали в `localStorage` одного браузера и больше
нигде. Это значит: почистил данные сайта — и семи шагов ремонта нет; открыл
игру на другом телефоне — начинай заново; открыл в десктопном Telegram вместо
мобильного — это другой webview, другое хранилище, снова пусто. Теперь всё это
держит воркер, таблица `profiles` (`worker/src/profile.ts`), а `localStorage`
остался копией: с неё рисуется первый кадр, пока не пришёл ответ, и она же —
всё, что есть у сборки без `VITE_API_URL` и у игры, открытой вне Telegram.

**Что считает сервер.** Баланс не хранится колонкой, а выводится: `players.stars`
(заработано, то самое, по чему ранжирует таблица) плюс `granted` минус `spent`.
Двух колонок, которые могут разойтись, тут нет по построению, и трата в магазине
по-прежнему не стоит места в рейтинге. Покупка — это `POST /profile/buy`, и
решает всё он: лежит ли эта вещь на сегодняшней полке, хватает ли монет, сколько
снять. Ни полка, ни цены при этом **не копия**, в отличие от таблицы наград в
`results.ts`: `PRICES`, `ROOM_STEPS` и сам бросок полки воркер импортирует прямо
из игры. Разница в том, что
покупает ложь — выплату клиент подделал бы себе в плюс, а цену он может
переписать только у себя на экране, снимут всё равно здесь.

**Отказ — это не ошибка, а свежая правда.** Любая ручка профиля отвечает 200 и
целым профилем, включая отказ. Клиент рисует покупку сразу, не дожидаясь сети
(магазин не должен тормозить), отправляет её и принимает то, что вернулось: если
сервер не согласен, счётчик монет встаёт на место сам, а кнопка снова говорит
`NEED N MORE`. Ошибка кода остаётся только у 401 (нет подписи), 403 (не
разработчик) и 503 (не задан `BOT_TOKEN`).

**Как переехали те, кто уже играет.** При открытии игра шлёт `POST /profile` и
кладёт в него `claim` — всё, что нашла в своём `localStorage`. Сервер верит этому
**один раз**: пока в его таблице для этого игрока пусто. Дальше арифметика
подобрана так, чтобы никто не оказался в минусе: `spent` ставится в то, во что
заявленные комната и шкаф обошлись бы по прайсу, а `granted` дотягивает баланс до
того числа, которое игрок видел на экране. То есть остаются и покупки, и монеты.

Дверь не закрывается на **пустой** заявке — иначе один заход с чистого браузера
(или с десктопа, где ничего не хранилось) навсегда похоронил бы настоящее
сохранение на телефоне. А тот, у кого сохранение и правда потерялось, получает
свои заработанные монеты обратно балансом: заработанное сервер помнит сам.

Это единственное место, где клиенту верят на слово, и оно намеренное: несколько
человек уже играют, и терять их прогресс ради принципа — значит терять именно то,
ради чего всё это делалось. Обратная сторона честная: пока игрок ничего не купил
на сервере, он может подправить своё же локальное число. Как только купил —
дверь закрыта, и дальше решает только таблица.

**Что это дало дуэли.** Перки — это одежда, а дуэль играется против человека,
который умеет открыть консоль. Раньше объект дуэли одевал обоих в то, что они
сами про себя написали в `hello`. Теперь — в то, что лежит в `profiles`, и
собственное слово принимается, только если строки нет вовсе (клиент, который
ни разу не синхронизировался).

**Дев-режим стал настоящим.** `src/ui/admin.ts` про себя пишет, что границей
безопасности не является и быть не может: id зашит в бандл и сверяется с
неподписанным `initDataUnsafe`. Бесплатные покупки и возвраты теперь проверяются
на сервере — по подписанному id против `ADMIN_ID` в `worker/wrangler.toml`. Не
задан — дев-цен нет ни у кого, что для чужого деплоя и правильно.

**Лестница лиг тоже здесь.** Она приехала последней и была последним, что
оставалось на телефоне, — а стоила дороже шляпы: от неё зависит, какие лиги
открыты и по какой таблице платят. Половина её и так была на сервере
(`players.top_league`, по которому дуэль платит каждому), так что разрез перестал
быть осмысленным: на новом телефоне человек видел одну бронзу, а дуэль платила
ему по короне. Победы прибавляет сервер при сдаче матча — там же, где начисляет
монеты, и по той же причине.

Единственное, чего сервер восстановить не мог бы, — это как раз лестница,
накопленная до сегодняшнего дня: он начинает считать победы только теперь, а всё
предыдущее существует лишь в том сохранении, которое переезжает. Поэтому победы
входят в заявку наравне с комнатой и шкафом и сливаются по максимуму на лигу.

**Что осталось на клиенте.** Архив компаний, язык, настройки доски и последняя
выбранная лига. Ничего из этого не прогресс — это удобства, и таблица профиля не
пытается быть общим облачным сохранением всего подряд.

**Две записи разом больше не затирают друг друга.** Каждая ручка читает строку,
меняет её в памяти и пишет целиком обратно, и между чтением и записью раньше не
стояло ничего: покупка, летящая три секунды по плохой сети, и нажатие WEAR за это
же время читали одну и ту же строку, а вторая запись клала первую обратно —
покупка выглядела бы как не случившаяся. Теперь `updated_at` служит и версией:
запись называет ту версию, которую прочитала, и `WHERE ... AND updated_at = ?`
отказывает, если строка сдвинулась. Отказ — не ошибка, а сигнал перечитать и
пересчитать решение по тому, что там на самом деле.

## Дуэль по ссылке

В меню теперь две кнопки. `PLAY` — лестница из лиг и бот напротив. `DUEL` —
живой человек: игра просит у сервера приглашение, отдаёт ссылку телеграмному
шерингу («отправить другу» открывает список контактов), и, когда друг её
принимает, оба садятся в **один и тот же матч**.

### Кто считает матч

Матч считает сервер. Durable Object (`worker/src/duel.ts`) собирает состояние
тем же `createMatch`, которым его собирает игра, крутит `step` по своим часам и
рассылает обоим по картинке на тик; нажатие приходит сообщением и проходит через
тот же `applyAction`, что и ход бота. **В браузерах не считается ничего.**

Очевидная альтернатива — оба клиента крутят один сид, а объект только
упорядочивает ввод — дешевле по трафику и была отвергнута по одной причине:
абилка двигает цены, и два клиента, разошедшиеся на один тик в том, *когда* она
сработала, остаток матча рисуют два разных графика и никак об этом не узнают.
Здесь график один, потому что симуляция одна. По той же причине абилки бьют по
одному и тому же состоянию, и по той же причине монеты за дуэль можно писать в
таблицу, ни у кого не спрашивая, что он там выиграл.

Цена решения — трафик: ~200 байт на тик, 160 тиков, порядка 30 КБ за матч.

### Что видит каждый

Сообщение всегда написано **для того глаза, в который идёт** (`src/duel/snapshot.ts`).
Свой трейдер приходит первым, `winner` и `resigned` перенумерованы, массивы
абилок переставлены — поэтому экран матча не пришлось трогать вообще: он
по-прежнему уверен, что человек это трейдер 0. Для того, кто читает, так и есть.

Книга соперника — то, за что продаётся DOSSIER, поэтому без него она уходит по
проводу нулями, и его сделки тоже. Уходит только сумма позиций: карточка
трейдера показывала её всегда, и прятать книгу не значит врать про карточку.

**Стороны садятся за разные деньги.** Ремонт офиса добавляет к стартовому
капиталу (см. «Ремонт офиса»), так что у двоих он почти никогда не одинаковый.
Объект читает шаги ремонта обоих из профилей на свистке — тем же способом и по
той же причине, что и одежду (`roomOf`, `outfitOf` в `worker/src/profile.ts`):
это матч против того, кто умеет открыть консоль, и его слово о собственном офисе
к делу не относится. Прочитанное один раз на старте матча, чтобы шаг ремонта,
купленный посреди дуэли, не менял уже идущий матч.

В `setup` уходят готовые **суммы**, а не количество шагов: сервер — единственный,
кто прочитал оба профиля, пусть он и считает. Клиент на билд старше, чем таблица
прибавок, тогда всё равно зеркалит ту игру, которую сервер реально крутит, а
клиент старше самого поля откатывается на ровные 10 000 — зеркало ошибается на
офис, а не ломается. Планка прибыли в +40 % считается на сервере от книги
**этого** места (`clearedBar(t.netWorth, t.startCash)`), иначе отремонтированный
офис получал бы бонус за меньший рост.

`src/ui/duel.ts` строит **зеркало** — обычный `MatchState` на том же сиде и той
же тройке компаний (отсюда расписание новостей, линии кварталов и перки в HUD) —
и больше никогда его не шагает. Каждый тик просто пишется поверх. Что это
делается правильно, проверяет `src/duel/snapshot.test.ts`: он играет настоящий
матч, гоняет каждый тик через формат и требует, чтобы к финальному свистку
зеркало и сервер совпадали до последнего знака.

### Приглашение

`POST /duel/new` заводит объект и отдаёт код. Ссылка ведёт **через бота** —
`t.me/<bot>?start=duel_<код>`, — а не сразу в игру: друг мог никогда не открывать
мини-приложение, и `?start=` это единственная дверь, которую Telegram для такого
открывает. Бот отвечает кнопкой на `WEBAPP_URL?d=<код>` (query, не фрагмент:
фрагмент Telegram занимает под свой `#tgWebAppData=…`). Имя бота воркер спрашивает
у Telegram сам — ещё одной переменной сборки не появилось.

Код — десять символов base32 без гласных: ни одно слово не складывается, и пары,
которые путает телефонная клавиатура, в алфавите не встречаются обе. Живёт
пятнадцать минут, и это всё, что отделяет постороннего от чужой дуэли.

Отвечает на такую ссылку сам воркер: у него вебхук на `/tg`, и ответ он отдаёт
**телом ответа на вебхук** — Telegram выполняет метод, который там найдёт, так
что обновление стоит одного похода по сети, а не двух.

### Позвать в чате

Третья кнопка под часами, и она для того, у кого никого нет. `SEND` нужен
человек, которому отправляют, `COPY` — место, куда вставить; у игрока с пустым
списком друзей нет ни того, ни другого, а есть пятнадцатиминутный отсчёт и
некуда его потратить. `CALL IT OUT IN THE CHAT` отдаёт приглашение общему чату
игры — тому самому, в который зовёт меню друзей, — и место достаётся тому, кто
первым нажмёт.

Пишет бот, не игрок: `POST /duel/shout` подписан, потому что заставляет бота
говорить в комнате, полной людей, и единственное, чего тут нельзя допустить, —
сделать это от чужого имени. Сообщение называет позвавшего, говорит, сколько
приглашение живёт, и несёт `url`-кнопку вместо `web_app`: **в группе Telegram
разрешает только первую** и отказывает в доставке всему сообщению целиком, если
встречает вторую. Кнопка ведёт в личку бота на `?start=duel_<код>`, то есть по
той же дороге, что и пересланная ссылка, — понимать её ничему новому не нужно.

Ограничение — один зов в десять минут на игрока, на сервере
(`worker/src/chat.ts`), по игроку, а не по дуэли: открыть новую дуэль ничего не
стоит. Отсчёт начинается только после того, как Telegram подтвердил отправку:
чат, до которого не достучались, не стоит игроку хода. Отказы экран называет
по-разному — «ты звал пару минут назад» это не «не получилось», и правило,
которое игрок вправе знать, честнее показать, чем спрятать за общей ошибкой.

Кнопки нет вовсе, если в `wrangler.toml` не задан `CHAT_ID`: сервер отвечает это
вместе с приглашением, и экран рисует то, что есть на самом деле, а не то, что
могло бы быть.

### Что происходит по дороге

Оба сели → сервер собирает матч и шлёт `setup` с доской и одеждой обоих →
экран VS (соперник сразу свой, без «ищем противника» и без возможности
пропустить: ждём мы не себя, а часы сервера) → 3–2–1 → тики. Отвалившийся сокет
переподключается сам, объект отдаёт место обратно и досылает всё, что было
пропущено; матч при этом не останавливается — рынок на сервере, и ему всё равно,
смотрит на него телефон или нет. Об этом на экране висит плашка.

### Плавность

Тик приходит по сети, а значит приходит неровно. Первая версия брала время
прямо от последнего прихода — и опоздавший на 90 мс тик упирал линию в
последнюю известную цену и держал её там, а пришедший раньше срока дёргал
вперёд. На вид это несколько подвисаний в секунду на вполне рабочем соединении.

Поэтому у линии свои часы. Она едет сама, тик за `tickMs`, а приходящие тики
гнут не её положение, а её **скорость** — линия, едущая на 10 % быстрее полсекунды,
незаметна, а прыгнувшая на 10 % вперёд заметна отлично. Целится она на 0.45 тика
позади прихода: этот запас и тратится, когда тик опаздывает. Ничего из того, на
что нажимает игрок, при этом не задерживается — тап уходит сразу, цифры двигаются,
как только пришёл ответ; отстаёт только линия, примерно на пятую долю секунды.

На модели с тиками ±200 мс линия не останавливается ни разу, а худший кадр —
1.4 обычного шага. У версии «время от последнего прихода» — простой в двенадцатой
части кадров и отдельные кадры в десять шагов.

Плашку «переподключаемся» тоже видно не сразу: разрыв, заживший за две с половиной
секунды, не показывается вовсе, потому что матч за это время ничего не потерял, а
плашка, выскакивающая на каждый опоздавший пакет, учит игрока её не замечать.
Первая попытка переподключения почти мгновенная, дальше с отступом. И раз в
двадцать секунд клиент шлёт `ping`: игрок, который не торгует, не отправляет
наверх ничего минутами, а в лобби — и все пятнадцать, и есть операторы, которые
такое соединение тихо кладут.

### Монеты

Считает сервер, по своей копии таблицы наград — той же, что за матч с ботом.
Одна поправка: **каждому платят по его собственной ступени лестницы**, а не по
лиге, на доске которой играли. Ступень берётся из `players.top_league`, то есть
из того, что сервер сам помнит, — иначе победа над другом на короне стоила бы
восемнадцать монет тому, кто из бронзы не выходил. Побед в лигу дуэль не
записывает по той же причине: друг, готовый проиграть десять раз, не должен быть
лифтом до короны.

## Друзья

Строка в профиле, и за ней — список друзей, а под ним `ADD A FRIEND`, которая
отдаёт ссылку-приглашение в шторку Telegram: та открывает список чатов, и
сообщение уходит в тот, по которому нажали. Ту же шторку показывает дуэль, и это
не совпадение — она и есть тот выбор контакта, который иначе пришлось бы
изобретать (`shareInvite` живёт в `src/ui/duel.ts` и переэкспортируется из
`src/ui/friends.ts`).

**Раньше это была круглая кнопка на рельсе, и рельса была не тем местом.** Правило
там простое: колонка внизу — места, куда идут, рельса — то, на что смотрят и что
собирают. Список людей ничем не загорается — на него не приходит ничего, что
исчезнет к завтрашнему дню, — а то, за чем на этот экран приходят (ссылка, код,
список), делается один раз и не смотрится. Поэтому счёт и дверь стоят в профиле,
а сам экран лежит за дверью.

### Ссылка

`https://t.me/<бот>?start=friend_<код>` — через бота, а не прямо в игру: тот, к
кому она попадёт, мини-приложение может не открывать ни разу, а `?start=`
единственная дверь, которую Telegram для такого держит открытой. Бот отвечает
одним сообщением с кнопкой, кнопка открывает игру на `?f=<код>`, игра читает код
из адреса, стирает его оттуда и открывает меню друзей уже подружившимися.

**Код друга — не приглашение в том смысле, в каком им является код дуэли.** Он
не истекает, не расходуется и один на игрока навсегда, так что ссылку можно
кинуть в общий чат и её нажмут четверо. Приглашение, которое надо чеканить под
каждого друга, — это поход по сети и обратный отсчёт ради того, чего никто не
ждёт; дуэли нужно и то и другое, потому что дуэль — это место, у которого прямо
сейчас кто-то стоит. Чем платим: подружиться может любой, у кого оказалась
ссылка. Сообщений и уведомлений дружба по-прежнему не даёт.

### Что за неё платят

**По 50 монет каждой стороне** (`INVITE_COINS` в `src/friends/protocol.ts`,
начисление в `worker/src/invites.ts`). Ровно первая ступень слота, так что у
награды есть имя, а не число: друг покупает тебе вещь. Это примерно полтора дня
обычной игры — достаточно, чтобы заметить, и достаточно мало, чтобы горизонт
гардероба в три-семь месяцев уцелел.

**Платят за друга, который остался, а не за друга, который тапнул.** Выплата
ждёт **третьего** доигранного матча приглашённого (`INVITE_MATCHES`), а сервер и
так отказывается принимать два результата от одного игрока внутри сорока пяти
секунд, — так что каждый фальшивый друг стоит полутора минут, которые нельзя
заскриптовать. Сверху потолок: **пять оплаченных приглашений за всё время**
(`INVITE_CAP`), то есть 250 монет — около трёх процентов гардероба.

**От чего это НЕ защищает, честно.** Гостевые сессии выдаются любому, кто
попросил, без доказательств чего бы то ни было — иначе приглашение не работало бы
вне Telegram вообще (см. «Где игра работает»). Значит, награду за приведённого
можно фармить, никого не приводя. Ничто здесь эту дверь не закрывает и не
притворяется, что закрывает; всё, что тут сделано, — фарм не стоит возни.

Таблица `invites` ключуется на **приглашённом**, и это остальное в одну строку:
приглашённым другом можно побыть ровно один раз, что бы человек ни активировал
потом. Отметка об оплате ставится до того, как двинутся монеты, и только если
`UPDATE` нашёл строку всё ещё неоплаченной.

Алфавит у кода тот же, что у дуэльного: base32 без гласных, десять символов,
шестьдесят бит. Ни один код не складывается в слово, и ни одна пара, которую
путает телефонная клавиатура, не входит в алфавит целиком.

### Список

Имя, сыгранные матчи и заработанные монеты — та же строка, что в рейтинге, из
тех же колонок и тем же CSS-правилом: это та же таблица, обрезанная до людей,
чьи имена что-то значат. Сортировка по монетам: в рейтинге игрок тридцатый,
среди своих друзей — нет.

### Что можно сделать со строкой

Тап по строке открывает маленькое меню на два пункта — `VISIT` и `DUEL`, —
привязанное к самой строке и закрывающееся тапом по любому свободному месту.
Закрывает его подложка во весь экран: она же и есть весь этот механизм, и
благодаря ей меню обходится без кнопки «отмена», которая заняла бы треть.

Меню `position: fixed`, а координаты считаются из прямоугольника строки в момент
нажатия. Не `absolute` внутри строки: список прокручивается, и меню, лежащее
внутри прокручиваемого блока, обрезалось бы по его краю. Если снизу не хватает
места, оно раскрывается вверх.

**`VISIT` — комната друга.** Открывается мгновенно и без единого запроса: комната
и одежда приехали вместе со списком (`Friend` в `src/friends/protocol.ts`) — они
достаются тем же запросом, одним лишним `LEFT JOIN` по `profiles`, поэтому
ничего не стоят, а гость не смотрит на спиннер поверх чужой спальни. Экран
собран из тех же трёх кусков, что и главное меню, — `Room`, `Character` и
карточка внизу, — потому что в этом и смысл: комната, на которую игрок потратил
все монеты, — единственное, что он в этой игре сделал, и гостю она должна
показываться ровно такой, какой её видит хозяин. Одна кнопка `BACK` и больше
ничего: гость не ремонтирует, не покупает и ему ничего не продают.

**`DUEL` — вызов по имени.** Та же дуэль, что и с главного меню, с одной
разницей: сервер просит бота **доставить приглашение этому конкретному другу**,
и оно приходит ему в Telegram отдельным сообщением с кнопкой «ACCEPT THE DUEL».
Никто никуда не носит ссылку.

Это единственное сообщение, которое бот **отправляет**, а не возвращает ответом
на вебхук, — и потому единственное, которому нужен настоящий поход в Bot API
(`sendMessage` в `worker/src/telegram.ts`). Id приватного чата совпадает с id
пользователя, так что строки в списке друзей хватает как адреса. Разрешением
служит сама дружба: бот может написать любому, кто его когда-либо запускал,
поэтому сервер проверяет, что эти двое действительно друзья, — иначе ручка была
бы способом заставить бота написать незнакомцу.

Сообщение называет позвавшего по имени. Приглашение, пришедшее само по себе,
обязано себя объяснить: анонимное «кто-то хочет восемьдесят секунд твоего
времени» — это то, как выглядит ссылка, которую переслал друг, а эта не пришла
ни из чьих рук.

Дойти оно может не всегда: тот, кто бота ни разу не запускал или заблокировал,
недостижим, и Telegram отвечает 403. Ссылка чеканится в любом случае и на экране
остаётся, а под часами вместо «отправь ссылку другу» стоит либо «приглашение
ушло к N», либо честное «N не получает сообщений от бота — отправь ссылку сам».
Не дошедшее сообщение не должно быть концом дуэли.

Считает всё сервер (`worker/src/friends.ts`, раздел «Друзья» в
`worker/README.md`): у клиента нет ни списка, ни кода, он их только рисует. Как и
рейтинг, экран честно называет каждый способ не показать ничего — сборка без
сервера, сервер, который не отвечает, и список, в котором пока никого, — вместо
вечного спиннера.

### Чат

Под списком, и под каждой заглушкой, которая встаёт на его место: «не с кем
играть? у игры есть чат» и кнопка, открывающая его через `openTelegramLink`.

Это единственный экран в игре, который бывает пуст не по вине игрока: ему
предлагают ссылку и некому её отправить. Поэтому последнее, что на нём стоит, —
комната, полная людей ровно в том же положении. Ссылка и ничего больше
(`CHAT_LINK` в `src/ui/friends.ts`), так что в отличие от всего, что выше, у неё
нет состояния, в котором ей нечего показать, — она есть и когда список пуст, и
когда список не пришёл вовсе.

Из того же чата возвращается дуэль: приглашение, позванное кнопкой «позвать в
чате», приходит именно сюда — см. «Дуэль по ссылке».

## Корпорации

Третья кнопка в колонке меню, между магазином с рынком и рейтингом. Раньше она
стояла круглой на рельсе и была там единственной, кто ломал её правило:
корпорация — это место, **куда идут**, а рельса для того, на что смотрят. Заодно
три круглых кнопки подряд тихо сообщали, что рельса — свалка для всего, что не
поместилось, а такого правила с экрана никто не прочтёт. Колонка после переезда
читается как «тратить · изучать · состоять · стоять в таблице».

Корпорация — это список игроков с именем на нём: до тридцати человек, одна на игрока, и раз в месяц
таблица, которая считает не сумму, а среднее. Общая форма в
`src/corp/protocol.ts`, серверная половина в `worker/src/corps.ts`, экраны в
`src/ui/CorpScreen.tsx` и `src/ui/CorpTopScreen.tsx`.

Чего в ней нет и не будет в этой версии: казны, войн, сундуков, ролей кроме
владельца и участника, членства в двух сразу и пуш-уведомлений. Всё это
перечислено не как план, а как граница: каждая из этих вещей тянет за собой
экономику или модерацию, а корпорация задумана как то, что можно добавить в
игру, ничего в ней не двигая.

### Лента, а не чат

**Свободного текста нет нигде.** Писать в ленту может только игра: кто вступил,
кто вышел, кто взял новую лигу, кто получил награду и кто зовёт на дуэль. Поля
ввода, в которое человек напишет слово, в этой функции не существует.

Причина прозаическая и не техническая. Поле ввода, доступное незнакомцам, — это
обязанность модерации, а обязанность модерации не выключается по вторникам. Её
нельзя завести на время, нельзя переложить на одного разработчика и нельзя не
исполнять: первое, что через такое поле приезжает, — это то, за что приложение
снимают со стора. Telegram при этом в одном тапе и умеет чат гораздо лучше, чем
его умела бы игра; строить здесь худшую его версию не за чем.

Что осталось, стоит больше, чем звучит: **в ленте, которую пишет только игра,
нет шума.** Каждая строчка — то, что действительно произошло, поэтому экран
стоит открыть. Обычный клановый чат на тридцать человек — это два активных
собеседника и двадцать восемь, пролистывающих их переписку.

Отвергнутые варианты, по порядку:

- **Чат с премодерацией.** Очередь, которую кто-то должен разбирать. Тот же долг
  модерации, только ещё и с задержкой, из-за которой чат перестаёт быть чатом.
- **Чат с фильтром по словарю.** Не работает ни в одну сторону: пропускает то,
  что написано с ошибкой, и запрещает фамилии. И создаёт ровно ту иллюзию, из-за
  которой на приложение потом жалуются: «у вас же есть фильтр».
- **Заготовленные фразы**, как в играх без чата. Ближе всего, но это всё ещё
  сообщения, которые пишет человек, — а значит, спам из тридцати одинаковых
  «привет» и необходимость их как-то ограничивать. Лента событий даёт то же
  ощущение присутствия, не требуя ни одного решения о том, что людям можно
  говорить друг другу.

Лента обновляется опросом раз в десять секунд, пока экран открыт, и
останавливается по `visibilitychange`, когда его не видно. Вебсокет здесь не
нужен и был бы хуже: у дуэли он есть, потому что там тик каждые 500 мс и обе
стороны должны одинаково понимать, когда сработала абилка; лента меняется
несколько раз в час, и держать ради этого открытое соединение весь вечер на
телефоне — это плата ни за что.

Хранится она ограниченно: последние 60 событий и ничего старше недели — что
наступит раньше. Оба ограничения, а не одно: под одним только счётчиком тихая
корпорация копила бы три месяца своей истории, а под одним только сроком шумная
теряла бы вечер. Подметается лента в момент записи следующего события, так что
никакой задачи по расписанию тут нет — тем же приёмом, которым в игре устроены
день и витрина.

### Приглашение на дуэль в ленте

Кнопка «позвать на дуэль» открывает ровно ту же дуэль, что и всегда: тот же
`POST /duel/new`, тот же код, те же пятнадцать минут. Отличается только то, кому
об этом сказали — другу бот пишет по имени, корпорации кладётся карточка,
которую видят тридцать человек. Карточка живёт ровно столько, сколько живёт код
приглашения, потому что за ней стоит место, у которого прямо сейчас кто-то
стоит.

Забирает её первый нажавший, и это `UPDATE ... WHERE taken_by IS NULL`:
изменить строку может ровно один, остальным карточка гаснет с именем того, кто
успел. Флаг совещательный — кто на самом деле сядет, решает объект дуэли, как и
при переходе по ссылке, — но именно он делает так, что тридцать карточек гаснут
вместе, а не двадцать девять человек по очереди упираются в занятое лобби. Тот,
кто карточку положил, может забрать её обратно всегда: он хозяин лобби и это его
способ вернуться в дуэль, от которой отошёл.

### Среднее, а не сумма

Это главное решение во всей функции, и оно в одну строчку (`averageOf`).

**Сумма — это рейтинг размера.** Корпорация из пятидесяти обгоняет корпорацию из
пяти, как бы те ни играли, и тогда таблица перестаёт быть про игру: единственная
стратегия в ней — набирать всех подряд, а место в ней говорит только о том, кто
активнее вербует. **Среднее задаёт вопрос, ради которого таблица заводилась, —
насколько хорошо играют те, кто внутри,** и заодно делает место в корпорации
чего-то стоящим: участник, который не играет, стоит корпорации места.

Чем платим, и это честная цена: среднее можно защищать, выгоняя людей, а тихий
участник становится обузой. Ограничивают это три вещи — потолок в тридцать
человек, порог в три участника для попадания в таблицу вообще и то, что за место
в этой версии ничего не платят. Давление здесь — гордость, а не деньги. Если за
место когда-нибудь начнут платить, на это число надо будет посмотреть заново.

Порог в три участника — против обратного перекоса: без него первое место займёт
корпорация из одного очень хорошего игрока, то есть таблица игроков в шляпе.
Три — наименьшее число, которое не может оказаться одним человеком и ошибкой
округления.

**По долларам считаются только заработанные.** Доллары планируется продавать за
Telegram Stars, то есть за настоящие деньги, и таблица по балансу была бы
таблицей того, кто больше потратил, — в такой никто не хочет ни участвовать, ни
проигрывать. Поэтому в сезонный вклад попадает не баланс, а выплата: сервер
записывает её в тот момент, когда сам её делает (`corps.credit`), и купленный
или выданный доллар мимо этой функции не проходит вовсе. То же самое с монетами:
считаются выплаты за матчи, те самые, на которых стоит общий рейтинг, а награды
за задания — нет, ровно по той причине, по которой они не идут и в
`players.stars`.

Заработанных долларов два источника: суточный бонус — то, что платят за заход, —
и **прибыль с продажи акций** — то, что платят за угаданную компанию.

**Прибыль, а не выручка, и это важно.** Продажа возвращает деньги, которые и так
были твоими: начисляй игра выручку, сезон чеканился бы из одной покупки и одной
продажи бесконечно. Поэтому в сезон идёт выручка минус то, во что обошлись
именно эти акции (`sellShares` знает оба числа).

**Убыток считается нулём, а не вычитается.** Это решение про игру, а не про
арифметику: сезон, который умеет идти назад, — это участник, которого можно
винить за плохую неделю, а в этой таблице должно быть приятно состоять. Чем
платим: терпеливый игрок может держать убыточные позиции и продавать только
удачные. Бесплатным это не делает спред — купленная и тут же проданная акция
возвращается на 2 % короче (`SPREAD`), так что круговая сделка не приносит
ничего, пока не угадано направление. Проверено обоими способами в
`worker/test/profile.test.ts`.

### Сезон

Сезон — календарный месяц по UTC, и таблица обнуляется первого числа. Вклад
копится за сезон, а не навсегда: иначе корпорации, основанные первыми,
несдвигаемы, и новой незачем существовать.

**Никакой задачи по расписанию для этого нет и не будет.** На строке участника
лежит ключ сезона (`'2026-09'`), и если он не совпадает с текущим, вклад просто
не считается, а при следующей записи перезаписывается, а не прибавляется. Это
тот же приём, которым устроены день (`src/daily/protocol.ts`) и витрина
магазина: переход происходит оттого, что ключ перестал совпадать, а не оттого,
что что-то сработало. Задача по расписанию, которая переводит всех на новый
сезон, — это то, что ломается в ночь на первое число, то есть ровно тогда, когда
на это кто-то смотрит.

Вклад привязан к паре «игрок + корпорация» и живёт на строке членства: ушёл —
вклад ушёл вместе со строкой, вернулся через час — начинаешь с нуля. Плюс сутки
кулдауна на вступление после выхода, иначе последний день месяца — это забег
всей игры в лидера: вклад не переезжает, но тело переезжает, и тридцать тел,
пришедших тридцатого, двигают среднее одной арифметикой. Кулдаун платит тот, кто
ушёл сам: исключённому и тому, под кем распустили корпорацию, он не начисляется —
это не их решение.

Что происходит с итогами прошлого сезона: пока ничего, они просто обнуляются.
Схема заведена так, чтобы историю и награды за место можно было добавить, ничего
не переделывая, — но их здесь нет.

### Тридцатое место

Потолок в тридцать человек — то место, где две заявки приходят в одну секунду, а
`COUNT(*)`, прочитанный и затем использованный, — ровно та гонка, которая
проигрывается. Поэтому `corps.members` — счётная колонка, а место занимается
одним оператором:

```sql
UPDATE corps SET members = members + 1 WHERE id = ?1 AND members < 30
```

Он либо изменил строку, либо нет, и всё остальное во вступлении висит на этом
ответе. Строка членства пишется следующим шагом, а не в той же пачке: у неё своя
причина не записаться (игрок успел вступить куда-то ещё — это ловит первичный
ключ), и проигравший обязан вернуть место обратно. Это `members - 1` в `seat`, и
ради этой единственной ветки вступление не является одной транзакцией.

Правило «один игрок — одна корпорация» не проверяется нигде: `corp_members`
ключится игроком, так что неверное состояние просто нельзя записать.

Переименование, смена девиза и смена двери идут через compare-and-set по
`updated_at` — та же схема, что у профиля (`worker/src/profile.ts`), и по той же
причине: два изменения, сделанных с разницей в секунду, не должны затирать друг
друга целыми строками. Четыре попытки, потом честное «пока ты смотрел, её
изменили».

### Жизнь и смерть

- **Ушёл последний участник — корпорация удаляется** вместе с лентой и
  заявками. Имя освобождается: уникальность имени — это свойство живой таблицы,
  а не вечная бронь.
- **Ушёл владелец, а люди остались** — владение переходит само, старейшему по
  дате вступления. Корпорация без владельца не должна существовать ни секунды.
  Старшинство, а не лучший игрок: старшинство нельзя нафармить за один хороший
  вторник.
- **Удалили аккаунт** — членство, заявки, кулдаун и все строки ленты с этим
  именем уходят в той же пачке, что и всё остальное (`corps.forgetting`, и
  `worker/test/delete.test.ts` следит, чтобы ни одна новая таблица не осталась
  забытой). Передачу владения при этом делает не удаление, а первое же чтение
  корпорации после него: удаление аккаунта обязано быть одной пачкой DELETE, а
  не походом переставлять чужие титулы.
- **Владелец, который перестал заходить,** — дыра, и она известна. В эту версию
  решение не входит.

### Имя, тег и девиз без модерации

Имя и девиз видит посторонний, а модерировать их некому — значит, защитой
работает сам алфавит. Разрешены только заглавная латиница, цифры и пробел:
имя 3–20 символов, тег 2–4 без пробелов, девиз до 60.

**Юникод не принимается вовсе, и это не упущение, а весь смысл.** Тридцать семь
разрешённых символов закрывают разом омоглифы (РАУРАL — это не PAYPAL, если `Р`
нельзя набрать), невидимые символы, RTL-переключатели и эмодзи, превращающие
список участников в чей-то флаг. Игре это ничего не стоит: у неё уже такая
типографика — компании пишутся тикерами, лиги кричат, все кнопки капсом.
Корпорация «ГАЗПРОМ» была бы белой вороной на собственном экране.

Сверху — короткий список запрещённых подстрок в конфиге, который проверяется и
по тексту, и по тексту без пробелов (`F U C K` — то же слово). Он ловит самые
ленивые пять процентов и ничего больше; настоящую работу делает алфавит.
Уникальность имени считается без учёта регистра и пробелов, иначе таблица
заполняется именами, отличающимися пробелом, — это не способ называться, а
способ занять чужое имя и сказать, что не занимал. Переименование — не чаще раза
в неделю: имя живёт в тридцати лентах и на чужих скриншотах.

Кнопки «пожаловаться» в этой версии нет. Место под неё в схеме есть.

### Знак и цвет

Основывая корпорацию, игрок выбирает ей знак и цвет; владелец может поменять их
потом. Каталог — `src/corp/emblems.ts`, он же и проверка: сервер сверяется с ним
перед записью, так что в колонку попадает только то, что эта сборка умеет
нарисовать.

**Почему каталог, а не загрузка картинки.** Ровно тот же довод, которым из ленты
убран свободный текст, а из названия — кириллица: картинка, которую принёс
игрок, — это обязанность модерации, а вся эта функция построена на том, чтобы её
не заводить. Закрытый набор ничего не может сказать, поэтому проверять после
факта нечего.

**Почему цвет — палитра, а не пипетка**, и вторая причина серьёзнее первой.
Пипетка позволяет выбрать цвет фона, а невидимый знак — это не выбор, который
кто-то хотел сделать, это ошибка, на которую потом смотрят двадцать девять
человек. Все десять проверены на том синем, которым покрашена игра. И этот цвет
уезжает в `style.backgroundColor` знака, который рисуется тридцати посторонним:
свободная строка там — это чужой CSS в твоём клиенте, а десять литералов — нет
(`cleanColor`).

**Наборов два, в одном списке.** Четырнадцать знаков, нарисованных для
корпораций (`public/textures/corps/`), и двадцать восемь, которые носят компании.
Второй набор не стоит ничего — все эти файлы и так в бандле, — и даёт тому, кто
встретил KRAKEN на доске, поднять его флаг. Компанейские идут вторыми и под
отдельным заголовком: корпорация — не компания, и по умолчанию предлагать
обратное не надо. Их id с префиксом `c:`, так что столкнуться с нашими они не
могут, а выведенный из реестра компаний список означает, что новая компания
добавляет знак и следить за этим отдельно не нужно.

Знак рисуется тем же `LogoMask`, что и логотип компании на рынке: белый силуэт
48×48, покрашенный CSS-маской. Один файл работает в любом размере и во всех
десяти цветах.

**Менять знак и цвет можно сколько угодно**, в отличие от названия, у которого
неделя кулдауна. Название можно каждый день делать новой шуткой; четырнадцать
рисунков и десять цветов — нельзя, поэтому защищать тут нечего, и неделя за смену
цвета была бы просто правилом.

Знаков было шестнадцать: якорь и ракету пришлось убрать, потому что `civic` и
`garage` во второй половине набора — это якорь и ракета, а две почти одинаковые
марки в одном пикере — не выбор, а повод приглядываться. Половину компаний
подвинуть нельзя, свою — можно. Всё, что будет рисоваться в этот набор дальше,
стоит сперва сверить с теми двадцатью восемью.

Три знака пришлось перерисовать после первого же взгляда на них в 18 пикселях —
том размере, которым их рисует список: ключ стоймя превращался в точку, у ракеты
закрашенное окно в маске не становилось дыркой, а бык с рогами вверх читался
зайцем. Это и есть причина, по которой в наборе нет ни одной детали тоньше
обводки.

### Иконка

Башня с пристройкой (`Tower` в `src/ui/components.tsx`). На рельсе уже есть
портфель и пара голов, так что третьей не могла быть ни ёмкость, ни человек, —
а корпорация в этой игре это имя над группой, а не сама группа, для чего здание
и годится. Две разновысокие массы делают ту же работу, что недорисованная вторая
голова в `People`: на 28 пикселях один прямоугольник — это дверь или карточка, а
два читаются как силуэт города сразу.

Пробовали и отвергли: рукопожатие (нечитаемо мельче 32 и означает «друзья» —
кнопку выше), щит (это гильдии, а не компании, и войн в игре нет), флаг (то же
самое плюс форма, которую в этом жанре уже использует всё), три головы (иконка
друзей с проблемой тесноты).

## Лиги

`PLAY` открывает лестницу из пяти лиг (`src/ui/LeagueSelect.tsx`, данные в
`src/ui/leagues.ts`) — это и есть выбор сложности. Горизонтальная лента с
`scroll-snap`, центральная лига увеличивается и выезжает вперёд, остальные
отодвигаются и гаснут.

| # | Лига | Соперник | Медиана нетворта бота | Побед до следующей | Монет за победу | За +40 % |
|---|---|---|---|---|---|---|
| 1 | BRONZE PIT | `rookie` | 9 879 | 3 | 3 | 2 |
| 2 | SILVER FLOOR | `easy` | 10 185 | 5 | 5 | 3 |
| 3 | GOLD DESK | `medium` | 12 135 | 7 | 8 | 4 |
| 4 | GLOBAL FUND | `hard` | 15 725 | 10 | 12 | 6 |
| 5 | BULL CROWN | `elite` | 18 170 | — | 18 | 9 |

Планка сложности — не процент побед бота над ботом, а **медиана нетворта самого
соперника** при старте в 10 000: именно её игроку надо перебить. В бронзе бот
заканчивает там же, где начал, под короной — почти вдвое выше.

Сначала открыта только первая лига, остальные серые, под замком и с неактивной
кнопкой. Ворота считаются по победам **в конкретной лиге**, а не суммарно:
`unlockedCount()` идёт снизу вверх и останавливается на первой лиге, чей счётчик
не добран, так что перепрыгнуть ступень нельзя, сколько бы побед ни было внизу.
Сдача — это поражение, и она не засчитывается: лестница проходится победами.

Победа, открывшая следующую лигу, показывается на экране результата плашкой
`... UNLOCKED`.

Победы считает сервер, а не браузер: они лежат в профиле рядом с комнатой и
шкафом, и прибавляются там же, где начисляются монеты, — когда матч сдан на
`/result`. Лига, которая открылась потому, что так сказал клиент, — не лига,
которую кто-то заработал. Сдача повторно тот же матч не засчитывает (см.
«Рейтинг и сервер»), сдавшийся приходит как поражение и не даёт ничего, а дуэль
на `/result` не приходит вовсе: лестница берётся у ботов, иначе друг, готовый
проиграть десять раз, — это лифт.

В `localStorage` остаются копия под `brokerstars.league.wins` — то, что меню
рисует до первого ответа, и всё, что есть в сборке без сервера, — и
`brokerstars.league.pick` (последняя выбранная лига). Вторая на сервер не поехала
намеренно: за каким столом ты сидел прошлый раз — это удобство, а не прогресс, и
на двух телефонах оно вправе отличаться. Массив побед короче текущей лестницы —
сохранение со старой версии — дополняется нулями.

Масштаб карточек считает `paint()`: каждой карточке пишется свойство `--near`
(1 в центре, 0 в стороне), а CSS превращает его в `scale` и `opacity`. React
перерисовывается только при смене центральной лиги, а не на каждом кадре
прокрутки. Расстояние меряется в **шагах ленты** (`offsetLeft` соседа минус
`offsetLeft` первого), а не в ширинах карточки: с зазором между карточками сосед
оказывается дальше одной ширины, `--near` у него всегда упирался в 0, и лента
переключалась рывком вместо роста под пальцем.

## Заставка перед матчем

`PLAY` ведёт из выбора лиги на экран противостояния (`src/ui/VersusScreen.tsx`):
фон `bg_vs`, слева выезжает игрок, идёт поиск соперника с кнопкой `CANCEL`, затем
справа выезжает противник — сначала чёрным силуэтом со светлыми стёклами очков,
как на референсе, потом подсвечивается. Тап в любом месте пропускает ожидание.

Силуэт делается не отдельным артом: все слои давятся в чёрное `brightness(0)`, а
поверх ещё раз рисуется очковый слой с `brightness(0) invert(1)` — отсюда пара
светлых пятен в темноте.

Набор одежды соперника генерируется случайно, с весами по редкости
(common 35 % … legend 5 %), чтобы противник в легендарном с ног до головы
воспринимался как событие. Генератор засеян от сида матча, поэтому один и тот же
сид даёт одного и того же противника. **Тот же набор надет на сопернике в матче** —
карточки обоих трейдеров теперь рисуют одетых персонажей, плоского спрайта у бота
больше нет.

Дальше идёт экран матча с отсчётом 3–2–1: симуляция всё это время заморожена,
таймер стоит, и стартуют они вместе.

## Покупательная способность

Потолка по плечу нет: купить можно на те деньги, что лежат на счету. Закрыть
позицию можно всегда, независимо от кэша.

Из-за этого нетворт на карточке трейдера — сумма двух очень разных вещей, и
покупать можно только на одну из них. Поэтому под ним стоят обе половины:
`CASH` и `HELD`, у обоих трейдеров. Показаны как есть, включая минусы, чтобы
они всегда складывались в итог: `HELD` уходит в минус под шортом, `CASH` — на
несколько десятков после MAX (количество считается от средней цены, а списывается
по цене со slippage и комиссией). Когда наличных не хватает даже на одну самую
дешёвую акцию, `CASH` краснеет, а мёртвые кнопки подписываются `NO CASH` вместо
того чтобы молча сереть.

Раньше свободный кэш стоял ещё и слева от переключателя размера, как `POWER`.
После разбивки это стал дубль `CASH`, причём расходящийся на вид: `POWER`
зажимался в ноль снизу, а `CASH` показывает уход в минус. Убран — одна величина
пишется в одном месте. Самого переключателя размера тоже давно нет: одно нажатие
всегда коммитит четверть кэша (`TRADE_FRACTION`), см. «Что сделано иначе, чем на
макете».

Раньше ограничение стояло на суммарном размере позиций (`нетворт x 1.5` из ТЗ), и
получалось контринтуитивно: шорт добавляет денег на счёт, но съедает лимит, так что
после шорта до предела было 24 207 наличными и ноль возможностей купить. Ключ
`maxLeverage` убран из конфига и дев-панели целиком — мёртвая ручка, которая делает
вид, что на что-то влияет, хуже её отсутствия.

**Побочный эффект, за которым стоит следить.** Шорт зачисляет выручку в кэш, а кэш
теперь единственное ограничение, поэтому «зашортить, потом купить» позволяет
набрать экспозицию сильно больше стартового капитала: в тесте вышло −53 URANUS
и +33 TET, то есть около 58 000 позиций на нетворт 9 500. Боты так не делают —
они берут долю от кэша, — так что на балансовых прогонах это не видно, а на живом
игроке может.

Прогон после отмены лимита (400 матчей): `medium` против `random` 86.3 %,
`hard` против `easy` 98.3 %, против «купить и держать» 88.5 %, близких матчей у
равных **66 %** против 60.8 % раньше, банкротств 0 %. То есть критерии не
пострадали, а матчи стали ровнее.

## Пауза

Кнопка с тремя полосками в шапке матча ставит игру на паузу: симуляция замирает,
таймер стоит, поверх выходит окно с текущим счётом и двумя кнопками — `RESUME`
и `SURRENDER`. Сдача завершает матч в пользу соперника (`resign()` в `sim/match.ts`)
и не приносит монет вообще, включая бонус за прибыль: иначе ранний удачный отрыв
можно было бы обналичивать сдачей, не доигрывая.

## Дев-кнопки в меню

В меню и магазине есть кнопки только для разработчика: `FREE ON/OFF` (покупки
ничего не стоят), `UNDO ROOM` (откатить последний шаг ремонта с возвратом монет) и
`DEV · REFUND THIS` в магазине (вернуть вещь и деньги за неё). Стартовый `common`
вернуть нельзя — на нём держится одетый по умолчанию персонаж.

Откат всегда возвращает цену шага, даже если он был куплен в бесплатном режиме, —
это заодно единственный способ добавить себе монет для тестов.

Показываются, если id пользователя из Telegram совпадает с `VITE_ADMIN_ID`
(в CI подставляется из секрета `MY_ID`), либо всегда в локальной `npm run dev`.

**Это не защита и не может ею быть.** Id попадает в собранный бандл и виден любому,
кто откроет JS, а сверяется он с `initDataUnsafe`, который Telegram не подписывает
и который подделывается тривиально. Кнопки просто убраны с глаз обычных игроков.

Всё, что действительно нельзя давать читерить, проверяет сервер — и **проверяет
по подписанному id**, а не по этой кнопке: бесплатные покупки и возвраты сверяются
с `ADMIN_ID` в `worker/wrangler.toml`, и не заданный `ADMIN_ID` означает, что
дев-цен нет ни у кого. `VITE_ADMIN_ID` решает только, нарисовать ли кнопку;
что она сделает — решают на той стороне.

## Дев-панель

Клавиша `D`, кнопка `PANEL` в дев-полоске меню или `DEV · OPEN PANEL` в окне паузы —
всё это видно только разработчику.

Тройного тапа в угол больше нет: невидимый квадрат 56×56 в правом верхнем углу
лежал поверх кнопки паузы и съедал все тапы по ней. Невидимые перехватчики поверх
интерфейса — плохая идея, поэтому вход в панель сделан обычными кнопками.

- сид + рестарт, случайный сид;
- скорость ×1 / ×2 / ×4;
- **show truth** — рисует справа от текущего тика будущие сегменты (`UP 3`, `DN 2`):
  видно, куда рынок собирается пойти, и можно сверить с этим поведение бота;
- чекбоксы `marketImpact`, `shorting`, `phases` — на лету;
- переключатель графика на абсолютные цены; `auto-scale` (по умолчанию включён)
  и min/max вертикальной шкалы, если понадобится пришпилить ось;
- выбор соперника: rookie / easy / medium / hard / elite / random / holder —
  те же семь ступеней, что лежат в `CONFIG.bot`;
- живое редактирование волатильности, дрифта, slippage, impact, затухания impact
  и комиссии (применяется со следующего тика). Плеча в этом списке нет с тех пор,
  как `maxLeverage` убран из конфига целиком — см. «Покупательная способность».

В dev-сборке есть консольная ручка: `window.bs.step(60)`, `window.bs.state()`, `window.bs.restart()`.

## Что сделано иначе, чем на макете

- **Портреты уменьшены** с ~250 px до 52–64 px. Они реагируют на дельту нетворта
  тремя состояниями (выигрывает — подсветка и лёгкий зум, ровно — норма,
  проигрывает — обесцвечивание).
- **Цвет развели с действием.** Цвет принадлежит компании: иконка (белый PNG,
  крашеный CSS-маской), линия графика и рамка её ряда. TET CORP — янтарный,
  URANUS — фиолетовый; ни один не совпадает с зелёным/красным, которыми
  показывается прибыль и убыток. SELL и BUY различаются стороной, наклоном
  параллелограмма, светлотой и подписью, а не цветом.
- **Шрифт системный.** Никакого файла не грузится и не лежит в репозитории:
  `ui-rounded` даёт на Apple-платформах SF Pro Rounded, который к мультяшному
  арту подходит, остальные откатываются на свой UI-шрифт. Тяжесть начертания
  (800) делает то, что раньше делал дисплейный шрифт. Если захочется вернуть
  фирменный вид — это один `@font-face` в `styles.css`.
- **Вёрстка телеграм-совместимая:** `100dvh` с фолбэком, `env(safe-area-inset-*)`,
  страница не скроллится вообще, кнопки сделок ≥ 44 pt. Помещается на 320×568.
- **Подсказок нет вообще.** Бегущая строка, врущие сигналы, фейковые компании и
  флаг `lyingSignals` выпилены из кода целиком — ни у игрока, ни у бота их больше
  нет. Гипотеза №1 из ТЗ этой сборкой не проверяется; чтобы к ней вернуться,
  придётся восстанавливать `sim/signals.ts` (см. историю правок).
- **Бот теперь читает график, а не ленту.** Смотрит движение цены за
  `lookbackTicks` и входит по направлению движения, если оно выбивается из
  собственного шума этой акции больше чем на `triggerSigmas` сигм. Порог считается
  от `noiseSigma` акции, иначе бот гоняется за каждым дёрганьем URANUS и не
  замечает TET вовсе. Держит позицию `holdTicks` и выходит — ставка на одно
  движение, а не навсегда. Информации о будущем у него по-прежнему нет: он видит
  ровно тот же график, что и игрок.
- **И играет он на все деньги** (см. «Бот перестал сидеть на деньгах»). Размер
  сделки считается от нетворта, а не от остатка кэша; свободные деньги
  раскладываются по доске сами; на новую идею бот продаёт то, что у него хуже
  всего. В рынке у него 82 % капитала вместо 38 %, а у `rookie` — 74 % вместо 9 %.
- **Три компании вместо двух.** TET CORP — дорогая и скучная, URANUS — качели,
  NOVA — середина (750, волатильность и длина сегментов между первыми двумя).
  Выбор «во что вложиться» перестал быть бинарным.
- Добавлены бейдж позиции на ряду, пунктирная линия средней цены входа,
  всплывающая цифра P&L на сделке, плашка новости, экран результата с графиком
  нетворта обоих игроков.
- **Переключателя размера сделки больше нет.** Ряд 10 / 25 / 50 / MAX стоял под
  карточками трейдеров и не игрался: размер выбирали один раз и к нему не
  возвращались, так что кнопки занимали строку, ничего не решая. Одно нажатие
  теперь всегда коммитит четверть кэша — `TRADE_FRACTION` в `src/sim/trading.ts`,
  рядом с исполнением, а не в экране. Само поле `fraction` в симуляции осталось:
  им пользуются боты, закрытие позиции целиком и стоп-лоссы. Строка на экране
  (`.ability-bar`) одно время стояла пустой под будущие абилки — и ряды под ней
  действительно не прыгнули вниз в тот день, когда абилки в неё встали.
- Симуляция шагает фиксированным тиком 500 мс, рендер интерполирует внутри тика,
  так что линия ползёт плавно, а не прыгает дважды в секунду.

## Баланс

Числа в `src/sim/config.ts`. Стартовые значения из ТЗ подкручены по итогам прогонов:
дрифт сегментов снижен, mean reversion поднят (пассивное удержание больше не
кормит), `refQty` снижен до 12 — при стартовом капитале 10 000 и цене 1000 сделка
это 3–8 акций, при `refQty: 50` slippage и impact были незаметны.

Критерий ТЗ «стратегия ▲▲▲ бьёт стратегию верить всем подряд» отпал вместе с
сигналами — вместо него в прогоне стоит `hard` против `easy`: проверяем, что
разница в качестве решений вообще на что-то влияет.

Главный рычаг для бота-графиста — по-прежнему `holdTicks`: бот, который сидит в
позиции дольше пойманного движения, отдаёт прибыль обратно на mean reversion.
Шкала выросла вместе с размером позиции — 40 / 32 / 26 / 22 / 18 вместо
26 / 18 / 11 / 9 / 8. Позиция теперь втрое больше, а slippage берётся с квадрата
заявки, так что ступень, переворачивающая книгу раз в четыре секунды, платит за
это комиссией: на старых числах низ лестницы обходился дороже верха.

Второй рычаг — `ignoreChance`, доля замеченных движений, которые бот пропускает:
0.78 / 0.68 / 0.60 / 0.52 / 0.45. Раньше он шёл от 0.78 до 0.03, и такой разброс
больше не нужен — деньги у всех ступеней одинаковые, разница только в том, что
они с ними делают, и слишком жадный верх лестницы пришлось бы гасить чем-то ещё.

`elite` сначала стоял на `sizeFraction: 0.45` — и ломался: два таких бота друг
против друга разгоняли рынок собственным impact'ом, 42 % матчей заканчивались
банкротством, а зеркальная дуэль давала 33.7 % вместо 50 %. Эта история теперь
только историческая: momentum-боты `sizeFraction` не читают вовсе, у них
`targetInvested` и `maxStockShare`, и роль того самого предохранителя играет
второй — при 0.55 ступень складывает весь счёт в две компании и зеркальные дуэли
перестают быть близкими (43 % против нижней границы в 50 %), при 0.45 держит все
три и близость возвращается к 58 %.

Лестница проверена по 300 матчей на ступень, `--seed=7`:

| Ступень | Побед у верхней | Медиана нетворта (против пассивного `holder`) |
|---|---|---|
| easy против rookie | 76.7 % | 9 647 против 8 706 |
| medium против easy | 91.3 % | 11 897 |
| hard против medium | 92.7 % | 14 419 |
| elite против hard | 81.7 % | 16 137 |

Каждая ступень бьёт предыдущую и ставит планку выше — банкротств по всей
лестнице 0 %. В скобках, для сравнения со старым ботом: ступени были
75.0 / 85.3 / 87.3 / 73.3 %, медианы 9 838 / 11 775 / 15 056 / 19 795. Планка
для игрока сдвинулась на краях лестницы, а не в середине: бронза и серебро стали
чуть мягче (бот, который весь матч в рынке, платит комиссию и slippage, а
отбивать их нечем — у `rookie` 22 % сигналов и реакция 2–4 с), `medium` остался
на месте, `elite` перестал быть настолько выше `hard`.

500 матчей, `npm run sim -- --seed=7 --runs=500 --acceptance`:

| Критерий | Требование | Факт | Было |
|---|---|---|---|
| `medium` против `random` | > 70 % | **72.4 %** | 81.6 % |
| `hard` против `easy` (замена критерия про сигналы) | сложность решает | **98.6 %** | 95.4 % |
| активная игра против «купить и держать» | заметно лучше | **77.6 %** | 83.0 % |
| отрыв победителя < 15 % (равные соперники) | ≥ 50 % матчей | **58.2 %** | 74.8 % |
| банкротство у `medium` | < 5 % | **0.0 %** | 0.0 % |
| воспроизводимость по сиду | тик в тик | OK | OK |
| выключение `shorting` или `phases` | не ломает игру | OK | OK |
| выключение `marketImpact` | не ломает игру | **см. ниже** | OK |

Два числа в этой таблице стоит читать вместе с прогоном, а не только по порогу.

Близких дуэлей стало 58.2 % вместо 74.8 %. Это прямое следствие того, что обе
стороны играют на весь счёт: разброс исходов шире, разгромов больше. Ручка —
`maxStockShare` (см. выше), и на 0.45 близость уже вытянута с 43 % до 58 %.

`--off=marketImpact` — единственное место, где бот стал заметно хуже: `medium`
против `random` даёт 48.0 % вместо прежних 73.0 % и медиану 9 764 вместо 10 554,
то есть без impact'а он в ноль. Slippage берётся с квадрата заявки и остаётся
включённым при выключенном флаге, а заявки теперь втрое крупнее — momentum
перестаёт окупать проводку. В игре флаг всегда включён; в прогонах это значит,
что `--off=marketImpact` больше не годится как способ померить «чистый навык»
бота.

Фиксированную вертикальную шкалу графика пробовали и откатили: сильный тренд
уезжал за верхний край и линию было не видно. Ось снова подстраивается под
видимое окно, код фиксированной рамки остался под флагом `chart.autoScale`.

Но подстраивалась она рывком. Окно едет каждый кадр, и в момент, когда старый
экстремум уходил за левый край, домен схлопывался разом — весь график дёргался
под линией, которая никуда не двигалась. На плейтесте это читалось как «график
слишком быстро меняется». Теперь нарисованный домен догоняет посчитанный
экспоненциально (`easeAxis` в `src/ui/chart.ts`, постоянная 260 мс), и **вниз
сужается только запас**: расширение происходит в тот же кадр, когда оно нужно,
так что всплеск никогда не обрезается и голова линии не превращается в
«за-шкалой»-клин. `chart.windowTicks` держится на 60 — это 30 секунд, полтора
квартала в кадре. Окно стоит задавать долей матча, а не секундами: на 120 с оно
поднималось до 90 тиков ради той же доли, и на 80 с вернулось обратно.

Это чистая подача: рынок, сделки и баланс не тронуты. Если график всё ещё
кажется дёрганым, следующий рычаг — уже сама волатильность (`noiseSigma`), и
она требует перепрогона баланса.

Соперника теперь выбирает лига, а не конфиг: `medium` (около 59 сделок за матч,
примерно одна в полторы секунды, 58.2 % близких дуэлей) — это третья ступень,
GOLD DESK. Раньше он стоял по умолчанию, и опасение «человек физически не
успевает тапать» лестница снимает сама: первые две лиги медленные, до `medium`
игрок доходит, набрав 3 победы в бронзе и 5 в серебре. Ручной переключатель
соперника остался в дев-панели, там же дев-только пресеты `random` и `holder`.

Одно расхождение с ТЗ: банкротство у `medium` не просто редкое, а нулевое —
бот закрывает позицию по `holdTicks` и с плечом 1.5 не успевает уйти в минус.
Механика жива и срабатывает у игрока, который держит MAX-шорт против новости;
если нужно именно «редко, но случается» у бота — поднимать плечо или убирать
`holdTicks`, но и то и другое роняет долю близких матчей (проверено: плечо 2.0
даёт 28 % близких вместо 55 %).

### Матч на 80 секунд и мёртвый старт новичка

Матч укорочен со 120 до 80 секунд, квартал с 30 до 20. Сама интенсивность бота
от этого не изменилась — `rookie` как торговал примерно 11 раз в минуту, так и
торгует, — но пауза перед его первой сделкой измеряется в секундах и не
сокращается вместе с матчем. Медиана первого хода стояла на 27 с: на 120 с это
четверть матча, на 80 с уже треть, а на p90 — 39 с, то есть половина игры,
в течение которой карточка RIVAL не двигается вообще. Выглядит как сломанный бот.

Полностью молчащих матчей при этом нет: перебор всех возможных досок во всех
пяти лигах (56 + 286 + 816 + 1771 + 3276 комбинаций, по 30 сидов на каждую) не
дал ни одного матча с нулём сделок. Дело именно в задержке старта.

Рычаг тут не `lookbackTicks` — он стоит под корнем в самом пороге
(`triggerSigmas × noiseSigma × √lookbackTicks`), так что укорачивание окна
одновременно опускает и планку. Проверено по 1000 матчей на вариант, лига
новичков:

| Что меняли у `rookie` | Первая сделка, медиана | Матчей с тишиной ≥ 30 с |
|---|---|---|
| ничего | 27.0 с | 34.7 % |
| `ignoreChance` 0.78 → 0.6 | 24.5 с | 22.9 % |
| `lookbackTicks` 11 → 7 | 27.0 с | 36.3 % |
| `reactionMs` до 2600 | 26.0 с | 30.8 % |
| **`triggerSigmas` 2.6 → 2.0** | **16.5 с** | **8.5 %** |

Взято последнее: `rookie.triggerSigmas: 2.0`. Первый ход вернулся к прежней доле
матча, сделок за матч стало ~19 вместо ~14 (столько же, сколько давали 120 с),
лестница цела — `easy` бьёт `rookie` в 75.0 % вместо 66.3 %, потому что новичок
теперь чаще заходит по слабому сигналу и чаще ошибается. Умнее он не стал:
`ignoreChance` 0.78 и реакция 2.2–4.0 с на месте, три четверти сигналов он
по-прежнему пропускает.

### Бот перестал сидеть на деньгах

Жалоба с плейтеста: бот ведёт себя ненастояще — почти не тратит деньги на акции,
и его баланс всю игру стоит на месте. Это меряется, и цифры жалобу подтверждали
(500 матчей, `--seed=7`, доля нетворта в рынке усреднённая по тикам):

| Ступень | В рынке было | Плоским (без позиций) | В рынке стало |
|---|---|---|---|
| rookie | 8.9 % | 34 % тиков | 74 % |
| easy | 15.4 % | 22 % | 81 % |
| medium | 37.8 % | 10 % | 82 % |
| hard | 60.7 % | 7 % | 84 % |
| elite | 73.8 % | 6 % | 82 % |

Причина была одна и не в настройках: заявка считалась долей **кэша на руках**
(`sizeFraction`), а кэш падает с каждой покупкой. Первая сделка `medium` брала
25 % от 10 000, вторая — 25 % от того, что осталось, и так до нуля. Бот, входящий
в позицию, автоматически терял право входить крупно, а в одной акции сидел
безвыходно: строка `if (t.positions[s] !== 0) continue` пропускала компанию,
в которой уже что-то лежало. Отсюда и неподвижный баланс: рисковала десятая часть
счёта, остальное лежало в кассе.

Что теперь делает `sim/bot.ts`:

- **Размер считается от нетворта.** Две доли вместо `sizeFraction`:
  `targetInvested` — сколько бот хочет держать в рынке (0.85 у `rookie`, 1.0 у
  `elite`), `maxStockShare` — сколько максимум может уйти в одну компанию.
  Остаток `1 − targetInvested` — это его оборотная касса, и он же служит зоной
  нечувствительности: пока свободных денег меньше, докупать бот не идёт.
- **Свободные деньги раскладываются сами.** Раз в тик остаток выше кассы уходит
  в компанию с самым пустым лимитом. Именно в пустой, а не в самую растущую:
  вариант «докупать лидера» был написан первым и выброшен — это вторая ставка на
  моментум, сделанная сдачей от первой, и она удваивала силу всех ступеней разом
  (`medium` против `random` давал 95.5 % вместо 83 %), после чего лестницу
  пришлось бы гасить обратно. Свободный кэш — это уборка, а не стратегия.
  Развёртка только покупает: шорт зачисляет выручку в кэш, и разрешить его тут
  значит каждый тик находить новые деньги и наращивать плечо до разрыва.
- **На новую идею бот продаёт худшее.** Кэша к моменту сигнала обычно уже нет,
  поэтому позиция, которая **в минусе** сильнее прочих, закрывается и платит за
  вход. Прибыльную ради погони за другой бот не трогает.
- **Сигнал против позиции — это выход.** Раньше бот просто не смотрел на
  компанию, где уже сидел. Теперь развернувшийся график по своей же бумаге
  закрывает её, а деньги уходят работать в другое место.
- **После закрытия компания остывает** на пол-`holdTicks`: без этого развёртка
  выкупала обратно то, что только что продала, и матч превращался в оплату
  комиссии по кругу. Свежий сигнал в остывающую бумагу пускают — повод вернуться
  и «больше некуда деть деньги» это разные вещи.

Мёртвый старт новичка (см. выше) при этом закрылся сам собой, и не тем рычагом:
деньги надо разложить, а не дождаться сигнала, так что первая сделка есть всегда.
Медиана первого хода — 2.5 с у `rookie`, 1.5 с у `easy`, 1.0 с у остальных,
матчей с тишиной ≥ 30 с — 0.0 % (500 матчей на ступень). Развёртка нарочно ждёт
`reactionMs[0]`: ступень, успевающая вложить весь счёт за полсекунды после
гонга, читается как автомат.

Балансовая цена вопроса — в двух таблицах выше: лестница цела, но сдвинулась
шкала `holdTicks`, порог `--off=marketImpact` больше не проходит, а близких
дуэлей стало меньше. Плюс новые метрики в `npm run sim`: строки `A in the market`
(доля нетворта в рынке и доля тиков без позиций) и `A cash swing` (размах кэша за
матч, в долях стартового) — именно по ним меряется эта жалоба, у `medium` было
138 %, стало 224 %.

## Чего в игре нет

Список несделанного, а не невозможного. Всё, что из него ушло, оставлено ниже
одной строкой — список, из которого ничего не вычёркивают, перестаёт быть списком.

**Звука.** Ни одного файла, ни одного обращения к `Audio` во всём `src/`.
Восьмидесятисекундная дуэль вокруг графика — жанр, который держится на обратной
связи, и тут её нет вовсе: ни тика сделки, ни колокола на закрытии квартала, ни
шороха на `BREAKING`, ни отдельного звука победы. Единственное в этом списке, у
чего нет ни одной причины, кроме «ещё не сделано».

**Подбора соперника.** `DUEL` сводит двух живых игроков в один синхронный матч,
но только тех, кто обменялся ссылкой: очереди, в которую можно встать одному, нет.
Отсюда же два дейлика, которые нельзя выполнить без друга, и чат как единственная
замена очереди.

**Смысла у портфеля.** Доллары покупают доли компаний, доли живут своей ценой и
своей таблицей — и на матч не влияют ничем. Ни дивидендов наличными, ни чего-либо,
что владение компанией давало бы за доской против неё. Стойка пока самоценна, и
это самая большая незакрытая петля в игре.

**Проверки результатов.** Матч детерминирован по сиду, `results` хранит и сид, и
лигу, и колонка `verified` заведена ровно под это — и стоит нулём в каждой строке.
Полная сверка требует лога действий игрока, которого сейчас не отправляют; см.
«Рейтинг и сервер».

**Финального арта.** Шрифт системный, соперник в дуэли одет генератором, часть
экранов собрана из тех же трёх кусков, что и меню.

Что из этого списка **ушло**: бэкенд и мультиплеер (`worker/`, «Дуэль по ссылке»),
аккаунты («Где игра работает»), кастомизация (магазин, гардероб, ремонт офиса),
метагеймовая покупка акций («Акции: стойка на рынке»).

**Что живёт только в этом браузере.** Каталог встреченных компаний, настройки
доски, язык, последняя выбранная лига, полка магазина на сегодня и отметка о
просмотренном туре. Чистятся вместе с данными сайта и на другом телефоне
начинаются заново. Ничего из этого не прогресс — это удобства, и им разрешено
отличаться на двух телефонах. Комната, гардероб, баланс, лестница лиг, награды и
портфель лежат на сервере и переезд переживают.
