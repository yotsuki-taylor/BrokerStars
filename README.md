# Broker Stars — прототип

Играбельный прототип биржевой дуэли для Telegram mini app. React + TypeScript + Vite,
график на Canvas 2D, симуляция — чистый TypeScript без DOM.

## Запуск

```bash
npm install
```

```bash
npm run dev
```

```bash
npm run build
```

Тесты симуляции:

```bash
npm test
```

Headless-прогоны для баланса:

```bash
npm run sim -- --seed=42 --runs=1000 --bot-a=medium --bot-b=random
```

```bash
npm run sim -- --seed=7 --runs=1000 --acceptance
```

`--off=marketImpact,shorting` выключает флаги в прогоне.

## Telegram

Игра — статическая страница; бот её не хостит, а только открывает. Поэтому нужны
две вещи: публичный HTTPS-адрес сборки и бот, который на него ссылается.

**1. Хостинг.** В репозитории лежит workflow `.github/workflows/deploy.yml`,
который на каждый push в `main` собирает проект и публикует на GitHub Pages.
Один раз включите Pages руками: Settings → Pages → Source → **GitHub Actions**.
После этого адрес будет `https://<пользователь>.github.io/BrokerStars/`.
`base: './'` в `vite.config.ts` уже настроен на подпапку, ничего менять не надо.

**2. Бот.** У @BotFather: `/newbot`, получить токен. Затем:

```bash
cp .env.example .env
```

Впишите в `.env` токен и адрес из шага 1. Файл в `.gitignore` — токен в
репозиторий не попадёт. Дальше:

```bash
npm run bot
```

Скрипт делает две разные вещи. Во-первых, одноразовая настройка: ставит синюю
кнопку **PLAY** рядом с полем ввода (`setChatMenuButton`) и регистрирует команды.
Это сохраняется на стороне Telegram — после первого запуска кнопка работает
всегда, даже когда скрипт выключен. Во-вторых, long polling: отвечает на `/start`
и `/play` сообщением с кнопкой запуска. Вот для этого скрипт должен быть запущен.

Зависимостей у бота нет, только Node 18+ ради встроенного `fetch`.

**Что игра берёт из Telegram.** `src/main.tsx` вызывает `ready`, `expand`,
`disableVerticalSwipes` и красит хром под фон игры; тапы по кнопкам сделок дают
haptic feedback. Имя игрока на карточке подставляется из `initDataUnsafe.user` —
это чисто косметика, данные оттуда клиентские и непроверенные, никаких решений на
них не завязано. Всё обёрнуто в guard, так что игра одинаково открывается и
обычной страницей в браузере.

## Меню, комната, магазин и звёзды

Игра открывается на меню: комната игрока во весь экран, одетый герой стоит в ней,
счётчик звёзд сверху, карточка следующего апгрейда и кнопки `SHOP` / `EQUIP` /
`PLAY` внизу. Заголовка «BROKER STARS» на этом экране больше нет — сценой стала
сама комната.

### Ремонт комнаты

Стартовая комната — набор `poor`, каждый шаг ремонта заменяет один предмет на
вариант `cosy`. Порядок и цены в `src/ui/renovation.ts`, всё в одном массиве:

| # | Что | Звёзд |
|---|---|---|
| 1 | стены и пол | 3 |
| 2 | кровать | 6 |
| 3 | дверь | 10 |
| 4 | окно | 15 |
| 5 | стол | 20 |
| 6 | полка | 25 |
| 7 | ковёр | 30 |

Покупка в два тапа: цена превращается в крестик и галочку, и пока висит вопрос,
комната **уже показывает результат** — предмет подменяется на `cosy`, отмена
возвращает как было. Так видно, за что платишь, до того как заплатил.

Ковёр — единственный предмет, которого в бедной комнате нет вовсе: до последнего
шага этот слой просто не рисуется. Порядок отрисовки снизу вверх:
`bg → rug → window → door → shelf → bed → table`.

Спрайты (`public/textures/room/`) лежат на общем холсте 1080×1920, так что комната,
как и персонаж, собирается наложением без сдвигов. Прогресс — в `localStorage`
(`brokerstars.room`), это просто число выполненных шагов.

Фигура персонажа намеренно небольшая и сдвинута вправо от центра: тумбочка стоит
ровно посередине сцены и при центральном положении полностью закрывалась.

Звёзды начисляются за матч по таблице в `src/ui/progress.ts`:

| Исход | Звёзд |
|---|---|
| победа | 3 |
| ничья | 1 |
| поражение | 0 |
| капитал вырос на 40 % и больше | +2 сверху |

Бонус начисляется независимо от исхода, поэтому проигранный, но хорошо
отторгованный матч всё равно что-то приносит. Планка именно «+40 %», а не «в
плюсе»: рынок сам по себе растёт, в плюсе заканчиваются **96 %** матчей, и награда
за это была бы не бонусом, а частью базовой ставки. Планку в 40 % берут 38 %
матчей. На экране результата видно разбивку.

Счётчик лежит в `localStorage` (`brokerstars.stars`); все обращения обёрнуты в
try/catch — в приватном окне и в некоторых webview доступ к хранилищу бросает
исключение, и игра не должна на этом падать, просто звёзды не переживут сессию.

Мета намеренно живёт в `src/ui/`, а не в `sim/`: симуляция про звёзды ничего не
знает, матч считается одинаково независимо от того, платят за него или нет.

### Магазин и гардероб

`SHOP` и `EQUIP` открывают один экран (`src/ui/Shop.tsx`) в двух режимах: в первом
видны все вещи, во втором — только купленные. Тап по карточке сразу примеряет вещь
на превью, кнопка внизу делает нужное действие: `BUY` / `WEAR` / `WEARING`.

Пять слотов (`hat`, `neck`, `torso`, `hand`, `access`) × пять редкостей. Цены в
`src/ui/wardrobe.ts`: 5 / 10 / 20 / 40 звёзд за uncommon…mythic. Всё в слоте
`common` выдаётся на старте — иначе меню открывалось бы на голом манекене.

При 2.26 звезды за матч это даёт такой темп: первый апгрейд комнаты — 2 матча,
вся комната — 49, первая небанальная вещь — 3 матча, одна мифическая — 18, весь
гардероб — 166. Раньше на всё уходило 570 матчей, то есть 19 часов, и до верхних
редкостей на плейтесте не доходил никто.

Спрайты (`public/textures/shop/`) экспортированы на общий холст 474×732, поэтому
персонаж собирается простым наложением картинок без сдвигов — этим занимается
`src/ui/Character.tsx`. Тот же компонент стоит на карточке игрока в матче, так что
купленное видно во время игры; соперник остаётся плоским `player2.png` — он бот, и
разная подача заодно помогает не путать, кто где. Порядок слоёв снизу вверх:

```
body → torso-down → neck-down → torso-up → neck-up → face → hair → hat
     → предмет в руке → access → hand
```

Где чья половина, описано картой `PIECES` в `wardrobe.ts` — три формы:

- `both` — вещь разрезана надвое, чтобы цепочка ушла под воротник, а воротник лёг
  поверх неё (все торсы, `neck-common`, `neck-mythic`);
- `up` — одна картинка, но лежать должна поверх воротника (`neck-legend`, бабочка);
- отсутствует в карте — обычная одиночная картинка в нижнем проходе.

Ключи карты обязаны совпадать с именами файлов `<slot>-<rarity>[-up|-down].png`.
Если не совпадут, слой просто не отрисуется — поэтому `Character.tsx` вешает на
каждый слой `onError`: битый слой прячется, а в консоль в dev-сборке падает имя
недостающего файла.

Голая рука (`hand.png`) кладётся последней: пальцы держат предмет из слота `hand`,
поэтому должны быть перед ним.

Миниатюры в карточках — кроп общего листа через `background-position` в процентах,
а не в пикселях: пять миниатюр фиксированного размера с зазорами не влезают в
320 pt, карточки должны уметь сжиматься.

Куплённое и надетое лежат в `localStorage` (`brokerstars.owned`,
`brokerstars.outfit`) с теми же try/catch.

## Тесты

`npm test` (vitest, 55 тестов). Покрыта симуляция (`src/sim/*.test.ts`) — то, что
в ТЗ названо единственным жёстким требованием, — ворота лиг
(`src/ui/leagues.test.ts`): лестница открывается ровно на последней недостающей
победе, ступень не перепрыгивается, награда растёт снизу вверх, у каждой лиги
свой соперник из `CONFIG.bot`, — и сглаживание оси графика
(`src/ui/chart.test.ts`): расширение мгновенное, сужение плавное, видимая точка
не прячется ни при каком времени кадра. Последнее нашло дыру: `NaN` в дельте
времени отравлял домен и гасил график до конца матча.

По симуляции:

- **детерминизм** — один сид даёт тик в тик тот же рынок, разные сиды дают разный,
  и повтор той же последовательности сделок приводит к тому же состоянию;
- **жизненный цикл матча** — ровно 240 тиков и остановка, автозакрытие позиций по
  цене последнего тика не меняет нетворт, победа у того, кто дороже, сдача отдаёт
  матч сопернику, банкротство обнуляет позиции;
- **торговля** — сделка списывает деньги и комиссию, slippage всегда против
  трейдера, шорт зачисляет выручку, средняя цена входа усредняется, закрыть
  позицию можно и без денег, знак реализованного P&L верен в обе стороны;
- **влияние на рынок** — сделка двигает цену и затухает по `decayPerTick`, с
  выключенным флагом не двигает;
- **рынок** — сегменты покрывают матч без разрывов, у флэта нет силы, новостной
  сегмент всегда силы 3 и попадает в новостную фазу, цена не выходит из клампа
  `[base*0.2, base*4]`, фазы идут по порядку и с флагом `phases: false`
  схлопываются в нейтральную;
- **выключение любого флага** не ломает матч.

Тесты проверены мутациями: перевёрнутый знак slippage роняет 3 теста, разрыв в
расписании сегментов — 2, сдача в пользу сдавшегося — 1.

## Структура

```
src/
  sim/          чистый TS, ничего не знает о React
    config.ts   ВСЕ числа баланса, один объект CONFIG
    rng.ts      mulberry32 + gauss, seeded
    market.ts   расписание сегментов, шаг цены, фазы, новости
    trading.ts  исполнение, slippage, комиссия, плечо, impact
    bot.ts      ИИ — читает график и ходит через тот же applyAction, что и игрок
    match.ts    createMatch(seed, cfg) / step(state) / runToEnd(state)
    types.ts    состояние матча
  ui/           React, только отображение
    chart.ts    отрисовка графика и графика нетворта (без React)
    leagues.ts  пять лиг: соперник, награда, ворота по победам
    progress.ts звёзды и таблица наград за матч
  headless/
    run.ts      прогон N матчей, статистика в консоль
```

Детерминизм: `createMatch(seed)` + те же действия = тик в тик тот же матч.
Проверяется автоматически в начале каждого прогона `npm run sim`.

## Лиги

`PLAY` открывает лестницу из пяти лиг (`src/ui/LeagueSelect.tsx`, данные в
`src/ui/leagues.ts`) — это и есть выбор сложности. Горизонтальная лента с
`scroll-snap`, центральная лига увеличивается и выезжает вперёд, остальные
отодвигаются и гаснут.

| # | Лига | Соперник | Медиана нетворта бота | Побед до следующей | Звёзд за победу | За +40 % |
|---|---|---|---|---|---|---|
| 1 | BRONZE PIT | `rookie` | 9 879 | 3 | 3 | 2 |
| 2 | SILVER FLOOR | `easy` | 10 185 | 5 | 5 | 3 |
| 3 | GOLD DESK | `medium` | 12 135 | 7 | 8 | 4 |
| 4 | GLOBAL FUND | `hard` | 15 725 | 10 | 12 | 6 |
| 5 | BULL CROWN | `elite` | 18 170 | — | 18 | 9 |

Планка сложности — не процент побед бота над ботом, а **медиана нетворта самого
соперника** при старте в 10 000: именно её игроку надо перебить. В бронзе бот
заканчивает там же, где начал, под короной — почти вдвое выше.

Сначала открыта только первая лига, остальные серые, под замком и с неактивной
кнопкой. Ворота считаются по победам **в конкретной лиге**, а не суммарно:
`unlockedCount()` идёт снизу вверх и останавливается на первой лиге, чей счётчик
не добран, так что перепрыгнуть ступень нельзя, сколько бы побед ни было внизу.
Сдача — это поражение, и она не засчитывается: лестница проходится победами.

Победа, открывшая следующую лигу, показывается на экране результата плашкой
`... UNLOCKED`.

Прогресс в `localStorage`: `brokerstars.league.wins` (массив побед по лигам) и
`brokerstars.league.pick` (последняя выбранная лига), с теми же try/catch, что и
остальная мета. Массив побед короче текущей лестницы — сохранение со старой
версии — дополняется нулями.

Масштаб карточек считает `paint()`: каждой карточке пишется свойство `--near`
(1 в центре, 0 в стороне), а CSS превращает его в `scale` и `opacity`. React
перерисовывается только при смене центральной лиги, а не на каждом кадре
прокрутки. Расстояние меряется в **шагах ленты** (`offsetLeft` соседа минус
`offsetLeft` первого), а не в ширинах карточки: с зазором между карточками сосед
оказывается дальше одной ширины, `--near` у него всегда упирался в 0, и лента
переключалась рывком вместо роста под пальцем.

## Заставка перед матчем

`PLAY` ведёт из выбора лиги на экран противостояния (`src/ui/VersusScreen.tsx`):
фон `bg_vs`, слева выезжает игрок, идёт поиск соперника с кнопкой `CANCEL`, затем
справа выезжает противник — сначала чёрным силуэтом со светлыми стёклами очков,
как на референсе, потом подсвечивается. Тап в любом месте пропускает ожидание.

Силуэт делается не отдельным артом: все слои давятся в чёрное `brightness(0)`, а
поверх ещё раз рисуется очковый слой с `brightness(0) invert(1)` — отсюда пара
светлых пятен в темноте.

Набор одежды соперника генерируется случайно, с весами по редкости
(common 35 % … mythic 5 %), чтобы противник в мифическом с ног до головы
воспринимался как событие. Генератор засеян от сида матча, поэтому один и тот же
сид даёт одного и того же противника. **Тот же набор надет на сопернике в матче** —
карточки обоих трейдеров теперь рисуют одетых персонажей, плоского спрайта у бота
больше нет.

Дальше идёт экран матча с отсчётом 3–2–1: симуляция всё это время заморожена,
таймер стоит, и стартуют они вместе.

## Покупательная способность

Потолка по плечу нет: купить можно на те деньги, что лежат на счету. Показатель
`POWER` слева от переключателя размера — это и есть свободный кэш; когда его не
хватает даже на одну самую дешёвую акцию, он краснеет, и серая кнопка `BUY`
перестаёт быть загадкой. Закрыть позицию можно всегда, независимо от кэша.

Раньше ограничение стояло на суммарном размере позиций (`нетворт x 1.5` из ТЗ), и
получалось контринтуитивно: шорт добавляет денег на счёт, но съедает лимит, так что
после шорта до предела было 24 207 наличными и ноль возможностей купить. Ключ
`maxLeverage` убран из конфига и дев-панели целиком — мёртвая ручка, которая делает
вид, что на что-то влияет, хуже её отсутствия.

**Побочный эффект, за которым стоит следить.** Шорт зачисляет выручку в кэш, а кэш
теперь единственное ограничение, поэтому «зашортить, потом купить» позволяет
набрать экспозицию сильно больше стартового капитала: в тесте вышло −53 URANUS
и +33 TET, то есть около 58 000 позиций на нетворт 9 500. Боты так не делают —
они берут долю от кэша, — так что на балансовых прогонах это не видно, а на живом
игроке может.

Прогон после отмены лимита (400 матчей): `medium` против `random` 86.3 %,
`hard` против `easy` 98.3 %, против «купить и держать» 88.5 %, близких матчей у
равных **66 %** против 60.8 % раньше, банкротств 0 %. То есть критерии не
пострадали, а матчи стали ровнее.

## Пауза

Кнопка с тремя полосками в шапке матча ставит игру на паузу: симуляция замирает,
таймер стоит, поверх выходит окно с текущим счётом и двумя кнопками — `RESUME`
и `SURRENDER`. Сдача завершает матч в пользу соперника (`resign()` в `sim/match.ts`)
и не приносит звёзд вообще, включая бонус за прибыль: иначе ранний удачный отрыв
можно было бы обналичивать сдачей, не доигрывая.

## Дев-кнопки в меню

В меню и магазине есть кнопки только для разработчика: `FREE ON/OFF` (покупки
ничего не стоят), `UNDO ROOM` (откатить последний шаг ремонта с возвратом звёзд) и
`DEV · REFUND THIS` в магазине (вернуть вещь и деньги за неё). Стартовый `common`
вернуть нельзя — на нём держится одетый по умолчанию персонаж.

Откат всегда возвращает цену шага, даже если он был куплен в бесплатном режиме, —
это заодно единственный способ добавить себе звёзд для тестов.

Показываются, если id пользователя из Telegram совпадает с `VITE_ADMIN_ID`
(в CI подставляется из секрета `MY_ID`), либо всегда в локальной `npm run dev`.

**Это не защита и не может ею быть.** Id попадает в собранный бандл и виден любому,
кто откроет JS, а сверяется он с `initDataUnsafe`, который Telegram не подписывает
и который подделывается тривиально. Кнопки просто убраны с глаз обычных игроков.
Всё, что действительно нельзя давать читерить, проверяется на сервере, а сервера у
прототипа нет.

## Дев-панель

Клавиша `D`, кнопка `PANEL` в дев-полоске меню или `DEV · OPEN PANEL` в окне паузы —
всё это видно только разработчику.

Тройного тапа в угол больше нет: невидимый квадрат 56×56 в правом верхнем углу
лежал поверх кнопки паузы и съедал все тапы по ней. Невидимые перехватчики поверх
интерфейса — плохая идея, поэтому вход в панель сделан обычными кнопками.

- сид + рестарт, случайный сид;
- скорость ×1 / ×2 / ×4;
- **show truth** — рисует справа от текущего тика будущие сегменты (`UP 3`, `DN 2`):
  видно, куда рынок собирается пойти, и можно сверить с этим поведение бота;
- чекбоксы `marketImpact`, `shorting`, `phases` — на лету;
- переключатель графика на абсолютные цены; `auto-scale` (по умолчанию включён)
  и min/max вертикальной шкалы, если понадобится пришпилить ось;
- выбор соперника: easy / medium / hard / random / holder;
- живое редактирование волатильности, дрифта, slippage, impact, плеча и комиссии
  (применяется со следующего тика).

В dev-сборке есть консольная ручка: `window.bs.step(60)`, `window.bs.state()`, `window.bs.restart()`.

## Что сделано иначе, чем на макете

- **Портреты уменьшены** с ~250 px до 52–64 px. Они реагируют на дельту нетворта
  тремя состояниями (выигрывает — подсветка и лёгкий зум, ровно — норма,
  проигрывает — обесцвечивание).
- **Цвет развели с действием.** Цвет принадлежит компании: иконка (белый PNG,
  крашеный CSS-маской), линия графика и рамка её ряда. TET CORP — янтарный,
  URANUS — фиолетовый; ни один не совпадает с зелёным/красным, которыми
  показывается прибыль и убыток. SELL и BUY различаются стороной, наклоном
  параллелограмма, светлотой и подписью, а не цветом.
- **Шрифт системный.** Никакого файла не грузится и не лежит в репозитории:
  `ui-rounded` даёт на Apple-платформах SF Pro Rounded, который к мультяшному
  арту подходит, остальные откатываются на свой UI-шрифт. Тяжесть начертания
  (800) делает то, что раньше делал дисплейный шрифт. Если захочется вернуть
  фирменный вид — это один `@font-face` в `styles.css`.
- **Вёрстка телеграм-совместимая:** `100dvh` с фолбэком, `env(safe-area-inset-*)`,
  страница не скроллится вообще, кнопки сделок ≥ 44 pt. Помещается на 320×568.
- **Подсказок нет вообще.** Бегущая строка, врущие сигналы, фейковые компании и
  флаг `lyingSignals` выпилены из кода целиком — ни у игрока, ни у бота их больше
  нет. Гипотеза №1 из ТЗ этой сборкой не проверяется; чтобы к ней вернуться,
  придётся восстанавливать `sim/signals.ts` (см. историю правок).
- **Бот теперь читает график, а не ленту.** Смотрит движение цены за
  `lookbackTicks` и входит по направлению движения, если оно выбивается из
  собственного шума этой акции больше чем на `triggerSigmas` сигм. Порог считается
  от `noiseSigma` акции, иначе бот гоняется за каждым дёрганьем URANUS и не
  замечает TET вовсе. Держит позицию `holdTicks` и выходит — ставка на одно
  движение, а не навсегда. Информации о будущем у него по-прежнему нет: он видит
  ровно тот же график, что и игрок.
- **Три компании вместо двух.** TET CORP — дорогая и скучная, URANUS — качели,
  NOVA — середина (750, волатильность и длина сегментов между первыми двумя).
  Выбор «во что вложиться» перестал быть бинарным.
- Добавлены переключатель размера сделки (10 / 25 / 50 / MAX), бейдж позиции
  на ряду, пунктирная линия средней цены входа, всплывающая цифра P&L на сделке,
  плашка новости, экран результата с графиком нетворта обоих игроков.
- Симуляция шагает фиксированным тиком 500 мс, рендер интерполирует внутри тика,
  так что линия ползёт плавно, а не прыгает дважды в секунду.

## Баланс

Числа в `src/sim/config.ts`. Стартовые значения из ТЗ подкручены по итогам прогонов:
дрифт сегментов снижен, mean reversion поднят (пассивное удержание больше не
кормит), `refQty` снижен до 12 — при стартовом капитале 10 000 и цене 1000 сделка
это 3–8 акций, при `refQty: 50` slippage и impact были незаметны.

Критерий ТЗ «стратегия ▲▲▲ бьёт стратегию верить всем подряд» отпал вместе с
сигналами — вместо него в прогоне стоит `hard` против `easy`: проверяем, что
разница в качестве решений вообще на что-то влияет.

Главный рычаг для бота-графиста — `holdTicks`. При 20 тиках он держит позицию
заметно дольше самого движения и отдаёт прибыль обратно на mean reversion:
`medium` выигрывал у `random` только 72 %. При 11 тиках — 89 %. По лестнице:
rookie 26, easy 18, medium 11, hard 9, elite 8.

`elite` сначала стоял на `sizeFraction: 0.45` — и ломался: два таких бота друг
против друга разгоняли рынок собственным impact'ом, 42 % матчей заканчивались
банкротством, а зеркальная дуэль давала 33.7 % вместо 50 %, то есть исход решал
не навык, а кто сходил первым. На 0.40 всё встало на место: 46.3 % в зеркале,
0 % банкротств против любого другого пресета, медиана 18 170.

Лестница проверена по 300 матчей на ступень, `--seed=7`:

| Ступень | Побед у верхней | Медиана нетворта (против пассивного `holder`) |
|---|---|---|
| easy против rookie | 66.3 % | 10 185 против 9 879 |
| medium против easy | 93.3 % | 12 135 |
| hard против medium | 91.7 % | 15 725 |
| elite против hard | 81.0 % | 18 170 |

Каждая ступень бьёт предыдущую и ставит планку выше — банкротств по всей
лестнице 0 %.

500 матчей, `npm run sim -- --seed=7 --runs=500 --acceptance`:

| Критерий | Требование | Факт |
|---|---|---|
| `medium` против `random` | > 70 % | **87.6 %** |
| `hard` против `easy` (замена критерия про сигналы) | сложность решает | **99.2 %** |
| активная игра против «купить и держать» | заметно лучше | **90.6 %** |
| отрыв победителя < 15 % (равные соперники) | ≥ 50 % матчей | **60.8 %** |
| банкротство у `medium` | < 5 % | **0.0 %** |
| воспроизводимость по сиду | тик в тик | OK |
| выключение любого из 3 флагов | не ломает игру | OK |

Фиксированную вертикальную шкалу графика пробовали и откатили: сильный тренд
уезжал за верхний край и линию было не видно. Ось снова подстраивается под
видимое окно, код фиксированной рамки остался под флагом `chart.autoScale`.

Но подстраивалась она рывком. Окно едет каждый кадр, и в момент, когда старый
экстремум уходил за левый край, домен схлопывался разом — весь график дёргался
под линией, которая никуда не двигалась. На плейтесте это читалось как «график
слишком быстро меняется». Теперь нарисованный домен догоняет посчитанный
экспоненциально (`easeAxis` в `src/ui/chart.ts`, постоянная 260 мс), и **вниз
сужается только запас**: расширение происходит в тот же кадр, когда оно нужно,
так что всплеск никогда не обрезается и голова линии не превращается в
«за-шкалой»-клин. Заодно `chart.windowTicks` поднят с 60 до 90 — окно стало
45 секунд вместо 30, лента едет медленнее, а потиковая рябь сжимается.

Это чистая подача: рынок, сделки и баланс не тронуты. Если график всё ещё
кажется дёрганым, следующий рычаг — уже сама волатильность (`noiseSigma`), и
она требует перепрогона баланса.

Соперника теперь выбирает лига, а не конфиг: `medium` (около 80 сделок за матч,
примерно одна в полторы секунды, 60.8 % близких дуэлей) — это третья ступень,
GOLD DESK. Раньше он стоял по умолчанию, и опасение «человек физически не
успевает тапать» лестница снимает сама: первые две лиги медленные, до `medium`
игрок доходит, набрав 3 победы в бронзе и 5 в серебре. Ручной переключатель
соперника остался в дев-панели, там же дев-только пресеты `random` и `holder`.

Одно расхождение с ТЗ: банкротство у `medium` не просто редкое, а нулевое —
бот закрывает позицию по `holdTicks` и с плечом 1.5 не успевает уйти в минус.
Механика жива и срабатывает у игрока, который держит MAX-шорт против новости;
если нужно именно «редко, но случается» у бота — поднимать плечо или убирать
`holdTicks`, но и то и другое роняет долю близких матчей (проверено: плечо 2.0
даёт 28 % близких вместо 55 %).

## Чего в прототипе нет

По ТЗ: кастомизации, аккаунтов, бэкенда, реального мультиплеера, звука,
финального арта. Мета-прогрессия начата сверх ТЗ — звёзды за победу, лестница
из пяти лиг и меню под магазин. Прогресс по лигам лежит в `localStorage`, то
есть чистится вместе с данными сайта и не переезжает между устройствами: чтобы
он что-то значил, нужен сервер, которого у прототипа нет. Бот умеет ровно одно — открыть игру;
результаты матчей никуда не отправляются и нигде не хранятся.
